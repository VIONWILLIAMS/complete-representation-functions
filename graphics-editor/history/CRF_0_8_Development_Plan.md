# CRF 图形计算编辑器 0.8 研发计划

**计划日期：2026-11-21（北京时间）**  
**计划版本：1.0**  
**状态：计划已制定；以下新增功能尚未实施或验收。**  
**现有代码基线：0.7.0，提交 bdcddbc3a4c57c1cfa79b42d9c28bd49b134873d。**

## 1. 北极星与本轮目标

长期目标：语言模型把用户意图转换为可执行、可编辑、可追溯的完备表示函数，由 CRF 直接计算像素，生成高质量图片，并继续扩展至视频与空间视觉。

0.8 研发周期围绕三个顺序关卡推进：

1. **G1：真实二维高斯重建。** 参考照片经过参数求解形成高斯场，仅依赖导出的表示即可重新渲染，并有完整像素误差证据。
2. **G2：对象级可控编辑。** 在同一高斯表示中完成墙面换色、信号灯移除与背景补齐、物品外观修改，边界、保护区与撤销可验证。
3. **G3：受限语言生成。** LLM 调用从真实参考中获得的对象／外观函数，生成新的实例与组合，并证明相对当前程序绘画基线有稳定改善。

G1、G2 是可验证工程闭环；G3 是必须通过实验的研究关卡。发布能力按实际通过的关卡标注，不能把拟定目标写成已完成能力。

**首个主验收案例继续使用原始红绿灯照片。所有旧案例保留。**

## 2. 当前事实与保留项

本计划基于现有源码和已有运行记录，不代表重新跑过全部测试：

- 最近十张图由独立 Canvas 程序绘画分支生成，没有调用像素高斯拟合器。
- 旧街景确有高斯核渲染，但精确原视角路径主要依赖完整源 RGB 和密集像素样本。
- 0.6 有水果轮廓与 UV 外观拟合，其范围有限，不能作为通用二维高斯拟合器。
- 最近十图的哈希验收证明导出完整性，不证明参考重建精度或照片真实感。
- 0.7 存在多个底层执行器。统一入口不能被表述为底层表征已经统一。

应保留：Street 红绿灯；苹果与梨子；实拍水果；湖景与其他旧案例；0.6、0.7 生成样例；最近十张二维程序图；已有导出、视频及视角入口。实际完整清单由 P0 从注册表生成，以上不是穷尽枚举。

## 3. 技术范围与共同架构

### 3.1 本轮主线

采用图像平面中的二维高斯表示与数值求解。GPU 可以用于二维计算，但不要求先建立三维网格或 Blender 场景。

两个入口共享新 CRF 状态：

- 照片入口：规范化观测 → 初始化 → 高斯拟合 → 对象与边界绑定 → 共享状态。
- 语言入口：语义规划 + 参考经验／对象函数 → 条件参数生成 → 约束修正 → 共享状态。
- 共同执行：共享状态 → 二维高斯渲染 → 实际图像 → 验收 → 局部修改／最佳候选保留。

高斯表示负责承载与渲染视觉信息；视觉先验负责提供无参考目标时的自然图像规律。视觉先验可以来自程序规则、检索案例、统计对象函数或训练模型，具体路线由受限实验比较。

### 3.2 最小中间表示

需要至少保存：

- 场景修订号、色彩约定、输出尺寸、种子、渲染器版本。
- 对象稳定 ID、类别、二维布局、锚点与连接／遮挡关系。
- 每个对象的高斯参数块：位置、正定协方差、颜色系数；分层合成需要的透明度另行定义，避免把不同渲染公式混为一谈。
- 对象掩膜与边界混合信息、保护区、允许影响区。
- 可编辑条件与参数范围、对参数块的明确映射。
- 背景层、推断区域及置信度。
- 来源标记：observed、inferred、generated；参考来源、算法及参数版本。

语义状态是兼容入口。旧 Canvas 程序先保留为整体程序节点；只有显式声明了对象接口的内容才能提供对象级编辑。不得声称能自动将任意 Canvas 源码反编译为完整对象结构。

### 3.3 “代码生成”和“100%”的口径

可审计程序可以消费高斯系数、对象函数参数和已学习数据；这些依赖、字节量和来源必须披露。拟合期间允许读取参考图，重绘验收阶段只允许读取声明的表示。

需要分别记录：

1. 导出 PNG 与画布一致：导出完整性。
2. 解码图与参考图完全相同：该参考图的无损重建。
3. 改色保护区完全不变：局部编辑约束。
4. 新生成图可信：生成质量，需要独立评价。

用户要求的 100% 像素复刻继续独立追踪。中间 PSNR／SSIM 目标不替代它。若使用逐像素数据或无损残差达到严格一致，作为独立模式公开报告，不能混入高斯拟合效率或新图生成成绩。

第一阶段优先结构化、高保真与可编辑，压缩率先作为观测量，不作为首要硬目标。

### P2：真正的二维高斯拟合器

**状态：待执行；最高优先级的新增能力。**

建议模块：

- fit/gaussian2d.py：可优化参数、初始化、求解与导出。
- web/crf-gaussian2d.js：二维高斯参考渲染器及浏览器执行接口。
- verification/gaussian_acceptance.py：参考像素、ROI、预算和耗时验收。

任务顺序：

1. 小图验证高斯公式、正定协方差、颜色空间及采样约定。
2. 对位置、协方差和颜色做有意义的数值／梯度检查，避免渲染可见但优化错误。
3. 建立固定核基线和可优化高斯基线。
4. 在 Street 原图上运行分预算拟合。
5. 根据误差尝试多尺度初始化、边缘约束、增密、拆分与剪枝。
6. 导出参数，在独立渲染环节重建；该环节不得读取完整原 RGB 或未声明残差。
7. 对完整保留照片测试同一算法，记录最差结果。

拟定预算档：4,096 / 16,384 / 65,536 个高斯。实际字节数包含参数、掩膜、索引及辅助数据，不能只报告高斯数量。预算增加必须作为新实验记录。

质量目标：

- 实验通路目标：Street PSNR ≥32 dB、SSIM ≥0.95，用于判断求解器是否具备继续投入价值。
- 0.8 高保真候选目标：Street PSNR ≥38 dB、SSIM ≥0.98；固定关键边缘带 MAE ≤5/255。
- 同预算对照可优化方案与固定核基线；需要改善整体误差且没有关键 ROI 的不可接受退化。
- 所有结果仍报告最大通道误差、精确 RGB 像素比例和最差 ROI。

这些是拟定工程目标，不是领域标准，也不是已达性能。P0 可在开发集上做一次资源校准并冻结正式目标；冻结后不能根据测试成绩下调门槛。

交付：拟合器、参数文件、重建图、误差图、固定裁切、预算—质量—耗时曲线、复现命令。

G1 通过条件：真实参数优化有效；独立参数重绘成立；固定预算下达到冻结的交付门槛；来源与残差口径清楚。若只达到实验通路目标，继续优化，不宣称高保真交付完成。

### P3：对象编辑、边界与背景补齐

**状态：待执行；依赖 G1 和 P1 的可用状态接口。**

任务：

- 对 Street 的墙、窗、杆、横杆、信号灯、路面建立对象绑定。
- 首轮可以使用已标注掩膜，但必须明确人工辅助范围；不能以此宣称自动语义理解完成。
- 实现墙色修改、信号灯删除、果物颜色修改。
- 建立软边界与混合像素处理，控制高斯跨对象覆盖。
- 背景补齐作为独立推断模块；输入、输出和可读取的数据边界明确。
- 接触／连接关系和阴影变化进入局部约束，不用整图重写解决局部修改。

拟定验收：

- 预先声明的保护区，相对编辑前渲染要求 100% RGB 不变。
- 有真实前景、背景和 alpha 的合成边缘样例：边界带 MAE ≤4/255。
- Street 固定边缘裁切以 200% 和 400% 查看；记录所有漏色、光晕、断裂，不仅展示最好区域。
- 人为遮挡墙面测试至少覆盖亮区、阴影区、墙缝和阴影边界。
- 平滑墙面补齐目标 MAE ≤5/255、SSIM ≥0.95；结构边界区目标 MAE ≤8/255，已知墙缝偏移 ≤1 像素。
- 被遮挡真值只由评估器读取；补齐模块不得获得原像素、其可逆高斯编码或包含真值的缓存。
- 实际信号灯背后墙面标为 inferred；检查完整、不透明、接缝与结构连续性，不报隐藏真值恢复率。

交付：可操作编辑案例、参数差异、保护区检查、边界测试、遮挡盲测、撤销复现记录。

G2 通过条件：在同一高斯状态中完成选中—修改—渲染—验收—撤销—导出闭环，并通过冻结边界／补齐门槛。

### P4：参考到对象函数，再到受限语言生成

**状态：待执行；研究关卡，不承诺自然获得通用照片生成能力。**

首批验证范围：

- 果物静物：苹果、梨、橙子，限定姿态与背景条件。
- 街景立面：墙、窗、杆与灯的有限布局变化。
- 自然场景局部：岩石、叶片、水面等外观函数，逐类验证，不直接把完整复杂风景纳入首轮成功承诺。

数据任务：

1. 每一类先检查 5–10 张实际参考的适用性与可对应性，再扩展至约 20–40 张可用样本。
2. 保存来源、使用条件、实例／拍摄组、颜色和视角条件。
3. 前景分离、二维配准、成像归一化。
4. 使用共享基底、锚点或集合匹配，建立不同照片间的高斯对应。
5. 形成“带条件与对应关系的函数样本”，不只形成图片文件夹。
6. 按物体实例、拍摄组和近重复关系划分数据，拟定训练／验证／测试为 60%／20%／20%；实际数量与覆盖随清单公布。

生成器候选：

- 可组合程序规则与已拟合外观函数。
- 共享高斯基底上的低秩系数、条件回归及残差统计。
- 如果上述能力不足，再评估条件参数预测器或高斯参数 token 生成模型；作为独立研究工作包评估数据与算力，不隐藏为普通代码修改。

LLM 负责：对象选择、二维布局、条件、关系约束和编辑操作。数值模块负责生成／求解连续高斯参数。无目标照片时不能虚构逐像素监督答案。

接口与模型实验：

- 复用现有真实参考取图能力，记录成功取图数和实际进入拟合的数据。
- 核对当前端点支持的推理配置，执行推理配置／多轮评审对照，记录实际请求与 token 用量。
- 每任务初始上限 3 个候选、最多 3 次高层反馈；数值优化单独设置固定预算。
- 每轮都使用实际渲染结果；最终测试不得通过无限重试选择性展示。

拟定生成验收：

- 先用 12 条提示完成方向性实验；正式门槛使用至少 30 条冻结、未参与调参的组合提示。
- 可客观判断的对象数量、颜色、相对位置等指令满足率 ≥90%。
- 对照当前 Canvas 路径：同提示、同输出分辨率、固定在线调用／求解预算；离线训练成本单列。
- 真实感盲评拟定偏好胜率 ≥65%，并要求按提示词作为统计单位的 95% 区间下界高于 50%；评审与平局规则预先冻结。
- 样本不足或仅单一模型自评时，结果只能作为方向性证据。
- 与最近参考重放比较，检查是否只是近重复；新布局、参数变化、来源与操作轨迹必须公开。
- 输出全部测试结果及失败类型，不只选最好看图片。

交付：对象函数库、参考清单、冻结提示集、原生生成参数与图片、基线对照、失败分析。

G3 通过条件：离开单一参考图仍能生成新实例／组合，满足条件控制并取得可重复的质量提升。胜过当前插画基线不等于已达到通用扩散模型或任何指定旗舰模型水平。

### P5：质量闭环、编辑器整合与交付

**状态：待执行；机制从 P2 开始贯穿。**

每个候选保存：

- 父修订、语义操作、程序与参数、随机种子。
- 参考来源、渲染器／求解器版本、输出图。
- 全部指标、最差 ROI、耗时、参数与辅助数据量。

2. 同预算比较主指标，关键 ROI 不得超出预先定义的退化容差。
3. 通过全部硬条件且有改进，才替换最佳候选。
4. 无改善按预算或停滞条件早停，保留最佳版本。
5. 管线修改必须通过旧案例回归与独立验证；修改最终测试暴露的问题后，应换新的测试集再作最终判断。

编辑器任务：

- 名称持续使用“CRF 图形计算编辑器”。
- 保持默认 Street 入口与全部案例。
- 新增高斯拟合状态、对象选择、参数编辑、前后对比、误差图和候选历史。
- 轻量首屏先可用，拟合与渲染有真实进度、取消、错误及恢复。
- 照片导入、参数导出、PNG 导出、重新导入均在实际浏览器验证。
- 预览延迟、首屏时间在固定设备上测试。可将预览 100–200 ms 作为初始优化目标，正式上限由 P0 探针冻结，不混用不同硬件成绩。
- 打包包含实际源码、依赖说明、必要参数、数据来源、运行命令和真实报告，检查文件存在与下载入口。

退出条件：用户可以通过同一工作台完成已通过关卡的闭环；旧案例不退化；导出完整性、参考精度和生成质量分别显示。

## 5. 数据与评估防混淆规则

### 图像编码／重建

给定测试照片，拟合器可以使用其像素求该照片的参数。这符合编码任务。冻结的是算法、超参数、预算和评价方法，不能根据该测试照片反过来调全局管线。

### 对象函数学习

训练对象与测试对象按身份／拍摄组分离。同一照片裁切、近重复图或连拍不能跨集合泄漏。验证集用于选择参数与轮次，最终测试集只作最终判断。

### 颜色与尺寸

固定规范化解码后的 8 位 RGB 作为验收基准；明确 ICC／sRGB 处理。拟合内部可以采用线性颜色，但输出比较约定必须一致。不得通过模糊、平移、缩小或重新压缩参考图来抬分，除非作为预先声明的独立实验。

### 性能与效率

同一项比较统一设备、分辨率、参数精度和预算。数据量统计覆盖所有实际依赖。高斯数量小于像素数量，不代表输出比 PNG 小；断网可重绘，也不代表原创生成。

| 表示与求解 | P2，高斯参数、渲染、优化 | 参数 schema、误差与预算报告 |
| 语义与边界 | P1/P3，对象绑定、软边缘、补齐 | 对象操作、保护区、遮挡盲测 |
| 参考与生成 | P4，参考数据、对象函数、LLM 计划 | 条件参数接口、独立生成对照 |
| 集成与评估 | P0/P5，基线、候选、编辑器与回归 | 冻结配置、真实浏览器闭环、完整交付 |

高斯参数更新、表示增密、对象函数修正、管线选择分层处理。首版优先自动化参数优化与候选择优；函数和管线级变更先生成候选，在固定验证条件下比较后再接受。不把一次代码重写称为已经完成递归自我改进。

## 7. 工作量、依赖与停滞处理

以下是有效工程工作日的初步估计，不是已承诺日期或自动后台运行安排。假设能够复用公开方法、算力可用、范围保持受限。

| 阶段 | 粗估 | 关键依赖 |
|---|---:|---|
| P0 基线与探针 | 0.5–1 日 | 资产完整、可用运行环境 |
| P2 / G1 高斯核心 | 3–6 日 | 拟合算力、渲染／优化正确性 |
| P1/P3 / G2 编辑 | 3–5 日，部分与 P2 并行 | 稳定参数 schema、边界与补齐 |
| P4 / G3 受限生成 | 5–10 日起，研究不确定性较高 | 可对应数据、条件覆盖、有效对象函数 |
| P5 发布验收 | 1–2 日，基础机制贯穿全程 | 上述关卡证据与浏览器运行 |

P0 完成后，根据一次实测校准范围与成本；之后按关卡推进，不因时间到了就宣布通过。

停滞处理：

- 拟合误差高：先检查颜色／坐标／梯度，再比较初始化、基底、尺度与预算。
- 边界错误：进入掩膜／混合像素／对象隔离修复，避免无目标整图重写。
- 训练重建好而新条件失败：增加对应关系、条件覆盖或改函数先验，不能只增加绘图笔触。
- 背景补齐失败：区分光照渐变、纹理和结构延续的失败，保留独立困难样例。
- 迭代无提升：保留最佳版本、记录失败假设、停止该分支，改下一项已声明实验。
- 管线修改导致旧案例退化：回滚该变更，保留失败证据。

## 8. 后续边界

静态生成通过后，再建立参数随时间连续变化、遮挡处理与时间一致性，推进视频。历史视频和视角功能继续保留；二维图像拟合成功不能直接证明真实新视角或完整三维恢复。

更广泛类别、高容量条件生成器和真正多视角生成需要独立的数据、算力与验收计划，不隐藏在 0.8 的工程工作量里。

## 附录 B：技术依据与使用边界

- GaussianImage，ECCV 2024：图像平面二维高斯表示、累加渲染与像素拟合。原始工作没有包含我们提出的语义对象编辑体系。
  https://www.ecva.net/papers/eccv_2024/papers_ECCV/papers/01421.pdf
- Instant GaussianImage，ICCV 2025：从输入图像预测初始化，后续微调，并调整高斯数量。不是文字到图片生成器。
  https://arxiv.org/abs/2506.23479
- GaussianImage++，AAAI 2026：失真驱动的增密、上下文相关滤波和量化。可供 P2 设计比较，不能直接证明 G3。
  https://arxiv.org/abs/2512.19108
- 2D Gaussian Splatting，SIGGRAPH 2024：三维场景中的二维面片与多视图重建；其“二维”含义与本轮图像平面方案不同。
  https://surfsplatting.github.io/
