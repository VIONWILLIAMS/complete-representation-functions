# 本轮实现报告：代码原生多题材渲染

日期：2026-11-23。范围：独立样片实验；没有修改原有 CRF 1.2 项目。

## 1. 已经实际完成什么

本轮编写并编译了一个 C++17 CPU 路径追踪器，使用 Python 程序生成场景几何和材质描述，实际运行渲染并查看预览，根据结果修改构图、光源位置和物体细节。完成图片的最终清单及实际参数以 `outputs/collection_manifest.json` 为准。

没有通过扩散模型生成底图，没有把照片贴在几何表面上，没有导入外部三维资产。程序输出线性高动态范围 PFM，随后使用有记录的传统图像处理生成 PNG。EXR 由原始 PFM 转换，已通过往返像素比较核验转换；它不是重新生成或经过色调映射的 HDR 替代品。

## 2. 内核与工程模块

| 模块 | 实现内容 | 实际边界 |
| --- | --- | --- |
| 场景描述 | 可读文本 DSL；Python 产生场景文件 | 独立实验接口，尚未接入既有编辑器 |
| 几何 | 球体、三角形、平滑法线、四边形；旋转曲面、树枝、叶片、布料等由代码展开 | 并非任意真实对象的自动建模器 |
| 加速 | CPU BVH 与多线程 | 当前实测输出来自 CPU |
| 材质 | 漫反射、GGX 金属、带高光的漫反射、平滑介电玻璃、Beer 吸收、程序纹理 | RGB 近似、简化介质处理；复杂叠层和焦散仍有限 |
| 光照 | 面积光、天空、太阳、NEE / MIS、多次反射、Russian roulette | 有限路径深度；复杂光路仍存在采样噪声 |
| 相机 | 透视、焦点与有限孔径 | 薄透镜近似，无完整镜组像差 |
| 辅助输出 | 材质色、法线、深度 | 来自场景求交，非图像模型估计 |
| 成像 | 可选 AOV 引导传统滤波、曝光、简化 filmic 曲线、sRGB、PNG | 无学习型降噪与超分辨率；非完整 ACES 流程 |

## 3. 场景设计与实际修订

五种题材用于暴露不同问题，而非证明任意内容都已达到照片级。

| 题材 | 主要观察点 | 已明确的局限 |
| --- | --- | --- |
| 产品特写 | 玻璃轮廓、金属反射、布光、表面细节 | 复杂多介质和精确焦散未充分覆盖 |
| 室内静物 | 陶瓷、木桌、玻璃、麻布，窗框投影与景深 | 程序木纹、叶片与织物仍有简化 |
| 建筑室内 | 空间关系、拱门、家具、间接照明、太阳投影 | 暗部噪声；家具与庭院植物不够复杂 |
| 山水景观 | 程序地形、植被、远近层次与空气透视 | 地形和树种规则性较强；雾为近似 |
| 沙丘景观 | 连续地形、沙纹、光影与构图 | 砂粒尺度和大气模型有限 |

室内静物修正了高频凹凸过强、光板遮挡阳光、枝条顶部裁切等问题。建筑场景修复了地板漏铺、填充光板进入镜头等错误；相机降低并靠近，增加圆角扶手、几何墙饰与窗外植被。所有这些修改都作用于源码或场景参数，并通过重新渲染检查，没有在最终图上补贴物体。

## 4. 可核查证据

- `src/renderer.cpp` 与 `scenes/`：实际运行算法与程序化场景。
- 对应 `*.json`：宽高、spp、seed、线程数、路径深度、场景规模、耗时和异常数。
- 对应 `*.development.json`：输入与输出哈希、曝光、传统滤波参数，是否改变输出尺寸。
- PFM / EXR：原始线性图像；法线、深度、材质色辅助通道用于观察真实几何。
- `run_sources/product/`：首张产品图运行时冻结的源码与哈希。
- `logs/`：编译、渲染与当前可执行检查记录；实际打包以交付清单为准。

耗时受到并行任务和 CPU 争用影响。单个运行日志不能当作独占服务器基准，更不能外推为 96GB GPU 的吞吐性能。

## 5. CUDA 的真实状态

已准备 CUDA 原型、共享数学生成器、编译脚本、有限渲染工作负载与检查脚本。本轮在无 GPU 主机上安装独立的 NVIDIA 官方编译组件，使用 NVCC 13.0.88、GCC 14.2、glibc 2.41 对未改动的源码快照完成 `sm_120` 交叉编译和链接，最终退出码为 0，耗时 86.62 秒。源码快照哈希与当时项目源码一致。GPU 设备执行、CPU/GPU 数值对照和性能验收仍未完成；本轮成图全部来自 CPU。

初次使用 NVCC 12.8.93 时，本机 glibc 2.41 与 CUDA 头文件中的 `sinpi/cospi` 系列函数异常声明冲突。换用官方支持 glibc 2.41 的 13.0 系列后，源代码编译通过；独立压缩包的 `lib/` 目录再通过工作区内的 `lib64 → lib` 链接匹配工具链布局，最终链接成功。没有补丁修改系统或 NVIDIA 头文件。**本机 CUDA 13 成功不代表远端 CUDA 12.8 已验证；没有把此二进制部署到远端。** 目标机器仍需以自身 NVCC 从源码重建。状态、官方包校验和、源码哈希及三次原始日志见 `logs/cuda_compile_status.json`。官方兼容性依据：[CUDA 13.0.1 Linux 安装指南](https://docs.nvidia.com/cuda/archive/13.0.1/cuda-installation-guide-linux/index.html)。

按用户补充的路径，另外安装了官方 Colab CLI 0.8.0 并尝试连接。Google OAuth 未完成；用户改走 tmate 后，授权提示已关闭。目前缺少 Colab 运行实例实际输出的 tmate 连接地址。没有申请新 VM，没有完成远程 `nvidia-smi`，也没有 GPU 实测。连接事实以 `logs/colab_connection_status.json` 为准。

既有 Colab 实例需要有效 Google 授权及明确的实例选择；示例中的 `my-session` 不是已核实的用户会话。只读诊断应面向已经核实的实例，避免使用可能自动申请机器的连接方式。官方实现依据：[认证流程](https://github.com/googlecolab/google-colab-cli/blob/main/src/colab_cli/auth.py)、[SSH 会话选择](https://github.com/googlecolab/google-colab-cli/blob/main/src/colab_cli/commands/ssh.py)。

原型使用 CUDA 软件 BVH；没有实现 OptiX，也没有调用 RT Core。真实 NVCC 编译通过说明该本机工具链能生成并链接目标代码，仍不能替代 GPU 运行、数值检查和性能测量。

后续顺序应为：目标机编译 → smoke 数值检查 → 预览目视检查 → 有限全分辨率任务 → 记录 GPU 利用率、耗时、显存和图像质量。命令与设备参数见 `CUDA_BACKEND.md`。

## 7. 仍需解决的质量问题

首先应提升对象表示：木纹需要更自然的方向与局部结构，植物需要层级分枝与叶脉，布料和陶瓷需要更可信的微结构。其次再优化积分器与采样，减少噪声和难采样光路的偏差。最后接入编辑器的参数修改、局部检查和自动重新计算。

本轮没有可严格配准的真实摄影参考，也没有使用独立物理渲染器完成全场景误差对照。因此可以验证图片确由代码生成、源码能够控制场景及局部细节；不能由此推导出“与真实照片一致”或“已经达到95%真实度”。

## 8. 静物显示层的亮点修正

静物原始路径追踪结果出现少量高方差亮点。最终展示采用独立、可复现的传统局部处理：以5×5中位数筛选候选，再用7×7内法线、albedo、深度接近的邻点和MAD判断孤立峰值。玻璃/金属主表面依照其精确albedo AOV签名保护，连续高光也保留。随后仍使用原有三次a-trous显示重建。

本次缩减167个原始像素，占5242880像素的0.00319%；其他原始线性像素不变。初次候选的滤波与显影合计约64.9秒；独立完整复现获得逐字节相同的PNG，重跑耗时以审计JSON为准。耗时会受CPU并发负载影响。最终PNG与预览已更新，其development记录、清单哈希同步更新。原始PFM/EXR哈希前后相同；没有修改渲染器或在图中添加内容。静物的整面高光保护策略不自动套用其他场景；山水另用下节记录的局部支持策略。

这是有偏的显示重建，不能作为无偏辐亮度结果。它可能削弱真实但未充分采样的焦散；保留玻璃小高光也意味着仍会保留少量无法判定的亮点。完整对照、原未抑制PNG、mask、参数和采用证明位于 `audit/still_life_display/`；复现命令为 `python3 tools/apply_still_life_display.py`。

## 9. 山水显示层的离散噪点修正

在查看最终山水及100%水面裁剪后，采用经审查的传统离群抑制候选。它不整体保护介电水面，仅对同法线、近albedo、近深度邻域中缺乏高亮支持的孤立峰值进行缩减，再做原有3次a-trous显影。亮度候选比值为1.6、线性阈值0.035、邻域半径3、MAD倍数10、最少12个同表面邻点；有至少3个高亮邻点支持时保留。

本次处理2049/6291456个原始像素（0.032568%），候选计算与显影约60.5秒。由于这些样本极亮，约削减4.33%原始估计总亮度。真实但尚未充分采样的太阳闪光或焦散也可能被削弱，因此仅作为有偏显示重建；原始HDR保持不变，不据此声称积分更准确。山体、树群、石头及水面几何/材质定义均未改，明显CG形态仍然存在。

正式PNG与预览、development及manifest哈希已采用经审查候选。旧PNG、完整逐像素报告、水面100%对照、mask、材料策略和HDR不变证据在 `audit/landscape_display/`。复现命令为 `python3 tools/apply_landscape_display.py`，支持缺少PNG/development的原始HDR/AOV输入，不做完整路径追踪重渲染。静物与山水分别使用上述两套保护策略，其余三个场景未启用额外离群峰值抑制。
