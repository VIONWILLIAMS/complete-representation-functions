## 3. 继续采用的技术方向

默认主线是自有程序几何、材质、灯光与相机作为可追溯数据，物理渲染提供可检查的参考，Gaussian 用于固定光照外观重现和交互预览，再用独立实验验证更复杂的细节或光照表示。

默认不引入外部照片贴图、现成网格或预训练生成模型，也不使用扩散增强。每个场景拟合自身渲染数据得到的高斯参数、可选小型 NHT 外观网络应明确登记为学习表示。照片重建、世界生成与 LPIPS 评价网络均是分开的可选输入/依赖，不应无声混入默认链路。

GaussianWorld 同名论文属于自动驾驶占据预测，不能当作当前摄影级场景生成引擎的直接实现依据。普通 RGB/SH 高斯记住既定照明下的外观，并未自动恢复可独立编辑的 BRDF 和光源。

## 4. Codex 最先应做的工作

### A. 接管资料与保留证据

1. 读本稿、研究报告、`scaffold/README.md`、`scaffold/ADAPTER_NOTES.md` 和两个配置文件。
2. 遵循目标仓库的现有版本、构建及目录约定；把研究准备状态写入项目状态页。
3. 原有 JSON 记录保留为历史证据。新运行使用单独的 run ID/输出目录，不覆盖历史报告后仍称其为旧证据。

### B. 在无 GPU 时可完成的接口工作

1. 实现并单独验证相机适配层，保存原始与目标像素中心约定，防止重复补偿。
2. 实现旧 PFM/AOV 读取与显式语义转换：行方向、线性颜色、有效 mask、t 与 Z、世界与相机法线、材质类别。
3. 从 `render_jobs.json` 构建有明确输入/输出/失败记录的有限任务执行器，先验证单场景解析和小图输出。不能因为已有 360 个文本文件就标为 360 张可用训练图。
4. 建立固定训练/验证/测试清单；将允许读取的 RGB 集合与设备资源预算实现为实际代码约束。

现有准备命令（从 `scaffold/` 执行；生成目标必须是新的空目录）：

```bash
python3 tools/prepare_fixture.py --output fixtures/procedural_reproduction
python3 tools/gpu_preflight.py --torch --torch-timeout 20 --output validation/new_machine_preflight.json
```

第一条只生成场景定义、相机与元数据；第二条只采集信息。它们都不会训练或渲染。

### C. GPU 到位后按门槛推进

1. **E0**：在实际设备上读取型号、可见显存、驱动、CUDA、PyTorch；选定并固定 gsplat commit 与完整依赖。执行小规模前向/反向、保存恢复和数值对照。
2. **E1**：先渲染少量标定视角，检查朝向、像素中心、颜色与 AOV；补独立解析/物理参考。再生成准备用于训练的图像并记录采样、随机种子、哈希和失败任务。
3. **E2**：只用 `neutral_top` 的训练视角做固定光照 gsplat 基线，完成保存/恢复、留出视角与轨迹输出。先小分辨率，再按实际吞吐安排扩大。
4. **E3a**：独立比较基础与抗混叠设置。gsplat 的相关开关不能直接宣称实现完整 Mip-Splatting。
5. **E3b/E4**：只有基线有效后，再分别研究 NHT、表面约束或显式 PBR 混合。每次只改变一个主要因素。
6. **E5/E6**：限定域的换灯与高清多题材输出最后推进；没有通过基线门槛时，不用堆高分辨率和训练步数掩盖接口问题。

## 5. 必须保留的接口约定

### 相机

- 米制、右手世界、Y 向上。
- OpenCV 相机轴：X 右、Y 下、Z 前。
- 4×4 矩阵 row-major；`viewmats` 使用 `w2c_opencv`。
- 夹具左上像素中心为 `(0,0)`，主点为 `((W-1)/2,(H-1)/2)`。
- 对本次审阅的 gsplat 接口，K 的 `cx,cy` 各加 `0.5` **一次**。默认 1024×768 的主点从 `(511.5,383.5)` 变为 `(512,384)`，图像数组不移动。
- 按目标实际固定的 gsplat 版本再次验证，不把当前 main 文档视为所有发行版行为。

### 深度、法线与颜色

- 旧 depth 为归一化主射线距离 t；对整数中心 `(u,v)`，`Z=t/sqrt(1+((u-cx)/fx)^2+((v-cy)/fy)^2)`。
- 旧 normal 为朝向观察侧的世界空间表面/着色法线，保存为 `0.5*n+0.5`。先解码，再按用途旋转，区分几何/着色法线和有效 mask。
- 旧 albedo 根据材质类型分别表示漫反射颜色、金属反射参数或玻璃逐米 Beer 透射色，不能一律作为漫反射率监督。
- PFM 文件行从底到顶；解码后图像数组为从顶到底。
- 物理混合必须在线性颜色域与明确曝光下完成。固定显影 RGB 可用于外观基线，但不能当成辐亮度直接参与光输运合成。
- 新的 material/object ID、diffuse/specular/direct/indirect、BRDF 参数图尚未实现。AOV 重构能量的检查应先于分量监督研究。

## 6. 数据划分与结果解释

夹具每组光照有 96 train、12 val、12 test 视角。三种高度各 40 个方位；验证连续方位索引 8–11，测试索引 28–31。没有额外保护角度带，边界可相距 9°，所以不能把这种留出协议称为任意外推能力验证。

三组光照共享相机划分；光照用途由消费配置定义：`neutral_top` 训练、`warm_left` 验证、`cool_right` 测试。图像文件存在不等于允许训练器读取。

| 协议 | 数据组合 | 能证明的能力 |
| --- | --- | --- |
| V | `neutral_top` × test views | 固定光照下的新视角 |
| L | `cool_right` × train views | 已知视角下的新光照 |
| VL | `cool_right` × test views | 新视角与新光照同时变化 |

验证集可用于选配置并记录选择过程；测试 RGB 不得用于重拟合颜色、曝光、颜色矩阵或挑选检查点。程序已知材质与测试灯光参数可以作为明确声明的物理分支输入，不能把这种更强监督设置与 RGB-only 重建混写。

## 7. 两种光照缓存必须分开

**E5a：固定光照入射辐亮度缓存。** 改灯后失效，需要重建。分别记录新视角质量、失效判定与重建成本；重建后的图像不计为零重算的跨灯光泛化。

**E5b：限定基底的预计算传输。** 只在声明的光照基底和几何/材质条件内有效。当前三个有限距离面积光场景不是远场低频环境光 PRT 基准，必须另生成基底、训练/验证/未见组合数据；这些数据当前不存在。

混合表示必须登记每个表面的渲染归属、遮挡关系和能量路径，避免把已经含光照的高斯颜色再当受光表面叠加一次。

## 8. 完成门槛与交付格式

- **环境门槛**：目标机实际前后向与保存恢复通过，有版本和设备报告。import 成功或 NVCC 编译成功不等于训练通过。
- **接口门槛**：相机、深度、法线、颜色和材质语义逐项核对；小场景实图与解析/独立参考一致到声明的误差范围。
- **训练门槛**：基线可复现、异常显式记录、训练与测试不泄漏；保留最差视角和失败区域。
- **质量门槛**：固定颜色域 PSNR/SSIM、可选 LPIPS、线性 HDR 误差、几何与连续轨迹分别评价。报告原生裁剪，不把指标转成“真实度百分比”。
- **物理门槛**：自家渲染器吻合是表示一致性，独立渲染/解析检查是物理数值参考，两者都不等于与真实照片逐像素一致。
- **性能门槛**：记录教师图像生成、训练、加载、纯渲染、导出、显存与磁盘。建议的 70% 显存软预算、2/6 小时上限及预热/重复方案均是待实现配置，不是现有调度器或测量结果。
- **输出**：每次运行交付输入/代码/依赖版本、命令与参数、成功/失败清单、原生 PNG、未滤波线性 HDR、AOV、预选 100% 裁剪、固定相机轨迹与实测资源记录。
