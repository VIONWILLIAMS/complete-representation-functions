# CRF 图形计算编辑器：二维代码生图

本轮增加独立的二维原生管线，入口为主编辑器顶部的「二维代码生图」。原有红绿灯、物品、观测与生成等案例继续保留。

## 实际运行方式

1. 编辑器后端 `/api/crf/canvas/generate` 调用 DeepSeek，检索场景资料并生成 `crf.canvas_program.v0.7` 图像程序。
2. 程序保存 id、标题、尺寸、种子、绘制源代码、参数及真实模型请求标识。
3. 编辑器在隔离的 Worker 中用 Canvas 2D 执行绘制，计算源代码与实际 RGBA 像素哈希。
4. 用户可编辑程序、通过语言要求修改、重新渲染、撤销，并导出 PNG 或程序 JSON。

本次十个场景均实际通过编辑器的场景选择与 PNG 导出完成，尺寸为 1200 × 800。导出文件的 RGBA 字节已逐一与编辑器显示的哈希比对，10/10 一致。证据见 `reports/direct2d07/editor_render_verification.json`。这是编辑器导出完整性的检验，不是与实拍照片一致的检验。

绘制内容来自二维路径、渐变、相关噪声、笔触、颜色场与像素合成。模型可以合成自行绘制的离屏 Canvas；本批没有加载照片纹理、三维模型、网格或光线追踪场景。

## 十个场景

晨雾湖泊、浪花海岸、秋日林间溪流、雨夜霓虹街道、雪山峡谷、夕阳梯田、春日樱花水岸、极光雪原、暖阳海滨村落、夏日花野。

全部初稿进行了真实模型请求；其中六个场景提交了编辑器实际导出的图片进行视觉反馈。樱花还进行了完整代码补发和一次实际运行错误修复。三次初稿被能力检测器错误拦截：它把普通注释里的 `three` 或 `window` 误认为 API 使用。纠正检测器后保留模型原始 source，不手绘替代画面。执行器兼容局部 W/H 声明与 rand 随机函数别名。

## 已知边界

- 当前画面仍明显属于程序绘画，尚未达到照片级真实感；不宣称已经达到扩散模型或其他旗舰模型的画质。
- 检索资料用于提供描述性参考，没有训练新的生成模型，也没有使用参考照片像素贴到画布上。
- 有些模型程序自行固定随机种子，编辑器改变 seed 后可能不产生像素变化；界面会比较前后哈希并明确提示。
- 当前编辑粒度主要是图像程序与语言修改，尚不等于全部内容都已有可单独选中的语义对象。
- 运行隔离使用不具同源权限的 iframe、受限 CSP 与专用 Worker，设有超时及离屏层预算；不声称能够绝对约束任意 JavaScript 的所有内存行为。

验收重点应继续放在可见的形态、材质、光照与局部细节质量，不能把程序运行成功或像素哈希一致等同于摄影真实感。
