# CRF 图形计算编辑器 0.10

交付日期：2026 年 11 月 22 日（北京时间）。这是可运行的研究版本，未达到通用照片生成的最终质量目标。

## 交付入口与内容

编辑器继续使用原站点：<https://crf-street-04-lab-4d86.laterafter950.chatgpt.site>。访问范围沿用原配置。

本版新增五个真实 DeepSeek 案例、一个旧街景高斯兼容对照，并保留原始红绿灯编辑案例与十个 0.9 案例。原始街景的换墙色、删除行人信号灯后的墙面补齐继续使用已有边界管线。

编辑器支持：选择物品函数、移动与缩放、替换或隐藏图层、线性光调色与曝光、近似高光保护、候选回放、参数工程导出、PNG 导出和五秒图像平面运镜视频。真正的三维新视角尚未交付。

## 论文如何进入系统

| 依据 | 本版模块与实际完成内容 | 能力边界 |
|---|---|---|
| GaussianImage | `web/crf-gaussian10.js`、`scripts/fit_gaussian10.py`：显式各向异性二维高斯、逐图参数求解、直接在目标分辨率求值。 | 是 CRF 自有实现，未完整复现论文压缩系统和性能。 |
| Instant GaussianImage | 确定性初始化、结构方向与图像方差预算分配。 | 未使用论文的训练编码器；部分交付资产采用较早的结构张量初始化，具体版本写入资产。 |
| Mip-Splatting | 像素足迹方差加入协方差，行列式幅度补偿，缩放时重新求值。 | 二维采样机制借鉴，未复现完整三维方法。 |
| GS-IR | 把颜色乘数、EV、低频照明和可选高亮残差保护分开。 | 当前分解是启发式；没有恢复真实材质、法线、BRDF 或光源。 |
| SHARP | 把二维平面视图和真实空间视角分开验收，缺空间证据时不判通过。 | 权重未安装、未推理；仅纳入能力边界与验收设计。 |
| GaussianAnything | 语言目标 → 对象与关系 → 局部函数资产 → 渲染，允许局部编辑与回放。 | 未运行训练生成器；分层编排不能替代视觉生成先验。 |

逐图拟合是求解这张观察的高斯参数；本版没有训练或微调神经模型，也没有把观察更新为一个共享的视觉生成模型。既有共享模型文件在实际实验前后摘要一致。

详细论据、官方主源和数值实验见 [PAPER_INTEGRATION.md](PAPER_INTEGRATION.md)。

## DeepSeek 实际执行与反馈循环

本次使用实际 `deepseek-flash` 服务，推理强度设置被传入上游。服务先输出受约束的场景参数，CRF 内核生成 RGBA，再把对应画面提交给模型评价；没有让模型返回任意 JavaScript 来执行。

共完成八个任务记录、十二张候选图。生成实验中记录到 **34 条有 usage 的供应商请求、265,431 个已知 tokens**，另有一次陶器评价因进程中断而结果与用量未知；这次未知尝试不计入已知 token 总数。单独的连通探测为一条请求、175 tokens，不计入生成实验总数。

| 实验组 | 任务数 | 候选数 | 有 usage 的请求 | 已知 tokens | 说明 |
|---|---:|---:|---:|---:|---|
| showcase-v1 | 5 | 5 | 15 | 108,622 | 五种场景初次生成，另有一次请求结果未知。 |
| repair-v2 | 1 | 1 | 5 | 66,610 | 修正水果遮挡与循环阻断；包含两次 Max 输出截断和续跑。 |
| polish-v3 | 2 | 6 | 14 | 90,199 | 每个任务三候选、两次反馈修正，六张都实际评价。 |

polish-v3 的真实感门槛在任务启动前设为 4.5/5；此前任务为 4/5。因此只能在各自固定合约内部选优，不能把跨任务的“通过”状态直接当成同一标准比较。水果最终保留候选 0，陶器保留候选 1；两者都没有采用最后候选 2。它们耗尽三候选预算时仍未通过更严格门槛，状态保留为待评审。

验收区分程序条件、像素测量和模型感知判断。模型评价与实际 RGBA 摘要、提交的图像摘要绑定；未知项不会自动变成通过。模型的自评分不是独立人类评价，也不是通用真实感形式证明。

循环机制详见 [LOOP.md](LOOP.md)。完整执行摘要见 [release_evidence.json](../../reports/v10/release_evidence.json)。

## 数值验证：已通过与失败都保留

- 新增 JavaScript 检查 64/64 通过，覆盖内核、运行循环、验证器、Provider 边界、二进制存储。Python 内核检查 4/4 通过；关键旧版回归检查 43/43 通过。
- 实际浏览器导出 1024 × 768 PNG，与 Node 使用同一场景和内核求值的 RGBA 每个字节一致。
- 实际浏览器导出的完整工程包含 8,192 个高斯；重放不读取原照片 RGB，仍与浏览器导出像素完全一致。
- 实际浏览器视频导出为 1280 × 720、24 fps、120 帧、5.000 秒。该视频应用了人工色彩编辑，演示二维平面运镜，不是真实新视角。
- 65,536 点的旧街景资产导入新内核后，667,000 个像素的 RGBA 与旧内核一致。这是求值兼容性，**不是原始照片的 100% 重建**。
- 同 8,192 点、同 667 × 1000 分辨率街景：旧求解器 PSNR 28.1290 dB；新线性求解 26.0171 dB；颜色回修后 27.4757 dB。新拟合质量仍回归，所以保留旧资产兼容路径。计算时间不同，这也不是同算力比较。
- 窄高斯缩小四倍的独立子像素积分测试：点采样线性 MSE 0.0031998；像素足迹近似 0.0000028346。这支持采样机制，不代表照片整体真实感已达标。

证据目录：`reports/v10/kernel/`、`reports/v10/browser/`、`reports/v10/generation/`。预览 JPEG 只服务候选列表；最终 PNG 的打包压缩逐文件验证 RGBA 不变。

## 重放和继续开发

```bash
npm run test:v10
python3 -m unittest discover -s tests -p test_gaussian10.py
npm run build
npm run dev
```

`保存工程` 导出的 JSON 嵌入当前全部高斯资产，适合独立重放；案例列表的轻量场景 JSON 则引用独立资产。调用生成服务需要通过既有服务端密钥配置，不把密钥写入工程或浏览器。新 API 路由为 `/api/crf/native10/generate`，支持 plan、generate、edit、critique。旧版端点与案例继续保留。

代码生成像素已经形成可重放链路，但最终高质量目标还缺：可靠的语义分层和亚像素边界、物体外观与源照片光照的分离、未观测结构和细节的生成先验，以及真实空间与时间一致性。继续增加推理次数只能搜索已有算子的参数；当缺陷需要这些缺失能力时，循环应输出能力缺口，而不是把自评分当成完成证明。
