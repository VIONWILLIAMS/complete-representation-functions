# CRF 0.10：论文借鉴、实现范围与仍待解决的问题

## 这一版推进了什么

CRF 的目标仍然是：语言模型把场景意图写成可执行、可编辑的表示函数，由图形计算内核生成图片，并逐步扩展到视频与可信的空间变化。编辑器是模型操作这些函数的工具。

0.10 补充了直接二维高斯求值、目标分辨率下的像素足迹过滤、线性光编辑与合成、可见贡献检查，以及保留旧资产画质的兼容路径。它们让“代码生成像素”更加明确、可检查，也为后续的生成与反馈循环提供了接口。

**这轮交付是对相关论文机制的选择性借鉴，不能称为完整复现这几篇论文，也不能称为已经达到通用照片生成模型的能力。** 尤其需要区分三个问题：能否表示一张照片、能否拟合已有照片、能否从语言创造此前没有观察过的高质量场景。前两个问题的进展，不会自动解决第三个问题。

## 论文与编辑器模块的对应关系

| 官方研究 | 值得借鉴的部分 | 本轮整合到哪里 | 已实现及验证的范围 | 尚未实现的部分 |
|---|---|---|---|---|
| [GaussianImage][gi] | 用显式二维高斯参数组织图像表示，将位置、形状、方向与颜色纳入可优化的函数。 | 二维计算内核、逐图参数求解、参数资产格式。 | CRF 自己的各向异性高斯求值；位置、两个尺度、角度及 RGB 系数的数值优化；从导出的参数资产直接渲染。 | 未完整复现论文的训练配置、压缩系统与全部实验；不能沿用其论文性能数字。 |
| [Instant GaussianImage / Instant-GI][instant] | 重视初始化质量与表示构建效率，避免每张图都从不合适的参数状态开始。 | 求解器初始化、误差驱动的预算分配。 | 采用确定性的均匀覆盖、图像方差划分、结构张量方向估计和残差分配；不使用神经初始化网络。 | **未集成其训练得到的编码器**，也没有因此获得一次前向计算即可达到其效果的能力。确定性算法只是本轮的工程借鉴。 |
| [Mip-Splatting][mip] | 渲染尺度变化时，应考虑像素覆盖的面积，不能只在像素中心取一个值。 | 原尺寸、预览尺寸与缩放视图共用的求值路径。 | 在投影协方差中加入像素足迹方差，并以行列式比例补偿幅度；直接在目标尺寸求值，另有独立数值积分测试。 | 当前是二维像素盒的高斯近似；**不是完整的三维 Mip-Splatting 实现**，也未完成跨照片、跨尺度的全面质量评估。 |
| [GS-IR][gsir] | 可自然编辑的场景需要区分材质、照明和成像结果；直接改最终 RGB 不等于恢复物理材质。 | 材质编辑、曝光与照明控制、高光近似。 | 线性光颜色乘数、EV 曝光、低频照明梯度；可选的中性高亮残差保护；对应数值与可逆编辑检查。 | **没有恢复真实反射率、BRDF、法线或环境光照**。源照片的光影仍保留在观察函数中；本轮也未实现物理逆渲染。 |
| [SHARP][sharp] | 单张照片重建与新视角应该有独立的空间表示和检查标准。 | 能力声明与验收门槛。 | 明确区分二维平移、缩放、旋转和真正的新视角；没有真实空间证据时，不把二维视图变化判为三维重建通过。 | **未安装或运行 SHARP 权重**，没有交付经其模型生成的真实新视角，也不能推断被遮挡部分已经正确恢复。 |
| [GaussianAnything][ga] | 生成架构中，语义条件与结构化表示需要连接起来，生成不能只停留在最后一张位图。 | 语言指令、场景对象、局部高斯资产之间的分层组织。 | 工程上把语义目标转换为场景与对象操作，再由局部函数资产求值；这是 CRF 的可编辑表示组织方式。 | **未使用其训练生成器或复现其训练流程**。层级编排能力不能替代学习到的视觉生成先验。 |

实现文件主要为 `web/crf-gaussian10.js` 与 `scripts/fit_gaussian10.py`。表中的“借鉴”指设计依据或可移植机制；没有安装、运行和验证的研究组件，不计入已交付能力。

## “不做模型训练”的准确含义

本轮没有训练神经网络，也没有用这些参考照片更新一个跨场景共享的视觉生成模型。

逐图拟合会调整某一张照片对应的高斯中心、尺度、方向和颜色系数。这是一个针对当前观察数据的数值求解问题。得到的参数资产只描述该观察及其可编辑的组织方式；它不会因为拟合了一个苹果，就自动学会任意苹果的背面、不同品种、不同光照和任意场景中的苹果。

这里仍然存在广义的参数优化。为了避免混淆，应称为“逐图参数求解”或“观察重建”，而不把它宣传成“不需要任何优化”。它与训练一个能对新输入泛化的神经生成器，作用和交付物均不同。

调用现成语言模型进行语义理解、规划和工具操作，也与训练视觉生成模型不同。语言模型可以提出构图、选择资产、修改参数、解释失败并安排下一轮工作；它的推理次数增加，不会自动为渲染器补上缺失的纹理、几何或反射模型。

## 本轮实际测到了什么

### 1. 直接函数渲染和跨运行时一致性

四个新物体资产都以 4,096 个高斯表示。渲染不读取原照片 RGB 位图；对象 alpha 是明确存储的观察覆盖度，而非已经恢复的三维几何。

| 观察重建资产 | 原生分辨率 | PSNR | 本轮拟合耗时 |
|---|---:|---:|---:|
| 苹果 | 253 × 261 | 34.34 dB | 约 9.6 秒 |
| 梨 | 255 × 414 | 35.89 dB | 约 14.0 秒 |
| 横切橙子半 | 195 × 182 | 32.54 dB | 约 6.0 秒 |
| 陶瓷花瓶 | 180 × 365 | 38.41 dB | 约 10.1 秒 |

这四个真实资产的 Python 与 JavaScript 原尺寸求值，所有可见像素的 RGB 差均为 0，alpha 也完全一致。这里的 PSNR 衡量与对应参考观察的重建误差，不能作为新组合场景“有多真实”的分数。

### 2. 新求解器并非在所有照片上更好

原街景采用相同的 667 × 1000 分辨率、相同的 8,192 个高斯进行比较：

| 配置 | PSNR | 判断 |
|---|---:|---|
| 旧 0.8 求解器 | 28.1290 dB | 同点数预算下更好。 |
| 新线性光求解器 | 26.0171 dB | 出现质量回归。 |
| 新求解器加固定点数的颜色回修 | 27.4757 dB | 有改善，仍未超过旧版。 |

这些配置的计算时间和求解工作量不同，不能称为同算力比较。颜色回修固定几何和点数，采用列预条件和实际损失回溯；它的改善说明颜色求解条件数及几何改变后的系数失配确实影响结果，但尚未解决全部误差。

因此，0.10 没有把新增算子包装成整体照片画质提升。生产兼容路径可以在运行时导入旧高斯资产，继续由新内核直接求值。真实旧街景资产包含 65,536 个高斯；转换后，667,000 个原生像素的 RGBA 与旧渲染器完全一致，不同字节数为 0。

**这项 100% 一致是两个渲染器对同一函数资产的一致性，不是与原始照片达到 100% 像素复刻。** 兼容路径的颜色基函数保留编码后的 sRGB 表示，求值后再进入线性光编辑与合成，因此也不能将它称为完整的线性辐射积分。

### 3. 像素足迹过滤有独立机制证据

在“一个很窄的高斯缩小 4 倍”的合成测试中，以每个输出像素内独立的 64 × 64 子像素积分作为参照：点采样的线性 MSE 为 `0.0031998`，像素足迹近似为 `0.0000028346`。

这个实验支持减少窄基函数缩小时的采样混叠。它不证明所有照片都变得更真实，也不证明完整 Mip-Splatting 已经复现。

### 4. 材质编辑与边缘仍有清楚的限制

`preserveHighlights` 根据亮度和中性分量分出一个高光相似残差，让颜色乘数主要作用于剩余部分。白色高亮与饱和色块的检查通过，但明亮的白色漫反射表面也可能被这条规则识别为高光。因此它是有用且可关闭的近似，不能据此宣称已获得物理材质。

alpha 采用独立覆盖度过滤，再进行浮点线性光合成，避免在合成中先量化导致的误差；这还不是颜色与 alpha 的联合解析积分。旧街景如果只作为一个整图资产导入，也不会自动获得经过验收的“墙面”分割。精确换墙色仍需要可靠的语义归属、边缘覆盖度和区域保护检查。

## 距离终极目标还缺什么

最核心的缺口是**生成先验**。高斯可以表示视觉内容，但表示能力本身不会提供内容。把若干参考照片拟合为函数，得到的是可重用的观察资产；要由任意文字构造此前没有观察过的照片，还需要能够补出结构、细节、材质、照明及其相互约束的机制。

第二个缺口是**对象与观察之间的分离**。目前一个对象函数仍继承源照片中的高光、阴影和视角。要在新场景中自然改变形态、光源和观察角度，需要更充分的观察证据，或明确标记为推断的几何和外观先验。单张图片通常不足以唯一确定这些隐藏变量。

第三个缺口是**可验证的质量反馈**。已有参考图可以逐像素比较；全新构图没有唯一的目标像素真值。验收应分别检查像素误差、对象与语义约束、边缘与遮挡、光影合理性、跨帧稳定性，以及人眼观察质量。没有真值的项应报告未验证，不能用较高的重建 PSNR 替代。

第四个缺口是**空间与时间的一致性**。二维运镜、缩放和旋转可以形成视频，但不能证明存在正确的三维世界。真正的新视角和物体运动，需要处理遮挡变化、此前不可见的区域、接触关系以及跨帧一致的细节。

## 后续迭代应怎样验收

1. **先建立逐资产的质量选择。** 在固定分辨率与点数下比较候选求解配置，记录实际耗时与误差。新配置回归时保留较好函数资产，继续公开失败结果；不得只靠增加点数来宣称算法优越。
2. **加强对象归属和边缘。** 为墙、灯、窗、路面等建立可检查的覆盖度与关系，测量编辑区域、受保护区域和边缘带的误差。删除物体后的背景补齐应有独立来源或明确的推断记录。
3. **将材质、照明近似与真实反演分开。** 继续保留可逆近似编辑，同时为需要物理重光照的任务建立证据要求。任何升级都应通过高光、边缘、遮挡和不同照明条件的专门案例。
4. **在有条件时引入可核验的生成或空间先验。** 不训练模型的约束下，可以评估经明确授权、可运行的现成模型推理，或继续改进参考检索与函数重建。是否采用外部模型，应单独说明其职责、来源和能力，不能把它藏在“代码渲染”的说法里。
5. **让推理循环围绕具体缺陷工作。** 每轮记录目标、修改的函数、可计算条件、结果和失败原因；只有受影响的指标通过，才接受该修改。条件检查可以构成可靠的验收系统，但有限条件通过不等于形式证明了一张任意图片具有真实世界的全部性质。

本轮对应证据集中在 `reports/v10/kernel/evidence-summary.json`，详细内核契约与复现实验见 `reports/v10/kernel/README.md`。后续版本应继续以这些可复查结果为依据，让计算内核、语义编排和反馈验证分别承担清楚的职责。
