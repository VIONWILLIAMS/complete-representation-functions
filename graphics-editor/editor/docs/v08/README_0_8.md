# CRF 图形计算编辑器 0.8

CRF 0.8 把“从照片得到可计算表示”和“由语言模型编排画面”接在同一条二维高斯路径上：参考图片经过实际下载、视觉语义分析和数值拟合，成为可保存、复用和修改的函数资产；DeepSeek 输出这些函数的语义 JSON，浏览器和离线工具使用同一个渲染器计算最终像素。

本版的可验收目标是让这条共同路径实际运行，并公开每一步的证据。它还不是具有通用自然图像分布知识的文本生图模型，也没有证明达到传统扩散模型的通用生成质量。

## 共同路径实际做什么

| 阶段 | 实际输入与操作 | 保存的证据 | 不应据此推断的结论 |
| --- | --- | --- | --- |
| 十轮检索 | DeepSeek 按不同主题和缺口进行真实搜索；每轮单独请求与检查点 | 查询、请求 ID、来源页、工具调用、失败与重试 | 搜索到一个网址不代表已看过照片 |
| 下载与去重 | 从允许的公开来源获取图片，检查容器、尺寸、字节大小和 SHA-256 | 原始下载、来源、哈希、去重与失败记录 | 不同 URL 不一定是不同摄影作品 |
| 图像语义学习 | 将实际下载图的预览提交给 DeepSeek 视觉，抽取主体、类别、估计框、颜色与光向 | 每张图的输入 ID、来源哈希、语义描述与局限 | 语义边界框不是精确分割，也不是像素拟合 |
| 高斯逆优化 | 从像素观测拟合中心、尺度、方向和有符号 RGB 系数 | 导出的高斯函数、误差历史、参数预算和最终指标 | 能复原已有图像不代表能凭空生成任意真实照片 |
| 对象函数 | 对可提取主体估计 alpha，裁出局部观测，再独立拟合 | 语义框、分割方法、人工修正记录、覆盖率与函数 | 自动估计 alpha 不等于真实物体边界 |
| 语义组合 | LLM 在函数目录内选择资产、位置、层级、颜色和曝光，输出受限 JSON | 完整候选场景、模型请求与结构校验记录 | 复制整幅照片、缩放或调色不算学会新主体 |
| 共享渲染 | `web/crf-gaussian08.js` 同时用于编辑器与 Node 导出 | 实际 PNG、渲染器哈希、RGBA 哈希和像素比较 | 输出哈希一致仅证明导出一致，不证明照片真实感 |
| 反馈与回滚 | 数值优化保留较优状态；画面反馈生成候选；无效候选不替换当前场景 | 最佳检查点、候选、错误与保留决定 | 这不是任意自我改写或通用自我演化系统 |

每轮的下载、看图、拟合是不同状态。动态执行数量由 [`web/assets/v08/learning.json`](../../web/assets/v08/learning.json) 给出，详细检查点位于 `reports/v08/learning/`。文档不将当前中间数量写成固定成绩；补查和修复属于原轮的追加尝试，不能把同一轮重试算成新的成功轮次。

### 哪些内容真正从像素拟合

`full_frame` 表示整张观测图的高斯函数，适合检验重建能力、提供背景或作为参考图变体。它不会自动获得“可单独操作的苹果”“可拆卸的窗户”等语义部件。

`semantic_object` 表示从具体观测中提取、带 alpha 覆盖率的局部函数。现有自动提取使用 **DeepSeek 视觉估计框 + OpenCV GrabCut + 边缘覆盖率平滑**。混合边缘颜色使用前景内部颜色延拓以减轻背景污染。估计失败时仍需要人工修正；相关记录保留在分割元数据中，不把人工辅助伪装成全自动恢复。

原始街景使用延续自早期版本的辅助语义标注及边缘处理，拆成墙、窗、立柱、支架、信号灯、路面等层。删除前景后显示的是后层已建好的背景函数；遮挡处的墙面属于补全假设，不是从单张照片中测得的真实隐藏像素。

### 哪些内容属于新画面

将已提取的苹果、梨、橙子或器物重新布置，在共同高斯渲染器中生成新的组合，是本版支持的“参考条件下的函数编排”。这种能力可以明确改变对象数量、排列、色相、曝光和可见性。

它尚不能保证对未收集的主体、从未观察的背面、复杂互反射或任意新场景给出真实照片。整图函数只改变缩放、裁切或整体颜色时，应标为“观测图变体”，不能用它证明从语言学会了完整场景分布。

## 已测街景结果与验收状态

以下结果针对原始 **667 × 1000** 街景，比较解码后的 RGB 像素，不是新图生成评分。高斯预算有限，导出的函数没有嵌入原图 RGB 数组或无损 RGB 残差。alpha 覆盖率可以独立保存，它不属于 RGB 真值。

| 表示 | 对象层 | 高斯数 | PSNR | SSIM | MAE，0–255 | RGB 完全相同像素比例 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 整图优化函数 | 1 | 65,536 | 43.4547 dB | 0.975536 | 1.151816 | 15.8253% |
| 可编辑语义层组合 | 18 | 62,329 | 41.2241 dB | 0.955130 | 1.5153 | 13.9088% |

整图数值来自 [`street.optimized.report.json`](../../web/assets/v08/gaussians/street.optimized.report.json)，共享 JS 渲染结果记录在 [`street-full.render.json`](../../web/assets/v08/renders/street-full.render.json)。18 层组合的实际像素记录在 [`street.render.json`](../../web/assets/v08/renders/street.render.json)，其 SSIM 来自对该导出图重新计算的独立 [`gaussian_acceptance.json`](../../reports/v08/gaussian_acceptance.json)。不要将早期 `street.reference.65k.report.json` 的未做同等几何优化结果混用为当前最佳结果。

原计划的高保真双门槛为 **PSNR ≥ 38 dB 且 SSIM ≥ 0.98**。整图函数与 18 层组合均达到 PSNR 条件，但两者的 SSIM 都低于 0.98，故该门槛均 **未通过**。完全相同 RGB 像素比例也远低于 100%。这比单纯报告“用了高斯”更能说明目前仍需改善的纹理、细边缘和局部误差。

浏览器的即时比较输出 MAE、RMSE、PSNR、最大误差和精确 RGB 比例；完整高斯窗 SSIM 由离线数值验收计算。没有对应实现结果时，界面与报告应保留 `null` 或“未测”，不能用另一种指标填充。

对改变了构图的新图，没有唯一原图可逐像素比较，应另外检查指令执行、对象边缘、接触、遮挡和外观合理性。原图重建指标不可以直接替代新图质量评价。

## 可复现运行

所有命令从仓库根目录执行。Node 版本至少为 20；离线拟合需要 Python、NumPy、SciPy、Pillow。自动对象分割另需 OpenCV。`g++` 或 `clang++` 用于可选的快速几何梯度循环；若编译器不可用，程序记录该情况并返回稀疏求解结果，不能假定仍能复现带几何优化的指标。浏览器执行 JavaScript 数值渲染，不依赖 GPU、Blender 或三维网格。

  --output /tmp/crf08-street-fit.json \

## 模型接口、证据和改进范围

生成与图像语义提取使用 DeepSeek 的推理模式 `high`。搜索保留实际工具证据；请求记录包含模型、请求 ID、token 用量、是否实际提供图像等。**不保存或返回推理正文**。托管编辑器的 API 密钥只存在服务端运行配置；目录、页面和下载文件不包含密钥。

本版的递归改进是受限的工程闭环：像素残差指导高斯预算和梯度更新；数值优化保留较优状态；无效 JSON 会请求一次结构修正；实际画面可提交模型评阅并产生候选；访问失败的来源显式更换为可读的公开来源。它没有训练 DeepSeek 权重，也没有让模型任意改写执行环境。

发布案例以每个场景保存的实际构图、图像评阅与修订记录为准；追加的打磨调用单独记录，不能从“每例若干轮”推定请求总数。目录中的 alpha 可见边界与下缘点是图像空间几何提示，能够帮助对齐二维画面，但不能证明对象已经放在真实平面上，也不能替代物理阴影与光照一致性的检查。

Depth Pro 2 只保留为后续深度适配的研究方向，本版未集成其模型权重，不依赖它产生当前图片。它的模型许可与代码许可应分别审查；本项目没有通过纳入研究权重来获得产品级深度功能。后续深度适配也需解决本项目旧深度假设与相机度量坐标的单位和方向差异。

请把以下内容一起交付，而不是只给一张结果 PNG：

1. [`FORMAT_0_8.md`](FORMAT_0_8.md)：字段、数学定义与渲染顺序。
2. [`PROVIDER_API.md`](PROVIDER_API.md)：生成、学习、看图与证据接口。
3. `web/assets/v08/catalog.json`：可用函数的 ID、尺寸、语义和资产位置。

5. 原始观测哈希、拟合报告与实际渲染报告。

另一个模型不需要重新发明绘图笔刷。它可以在相同目录中选择已学函数，输出同一 DSL，再交给同一个渲染器得到可比较的像素结果。更强的通用生成能力仍取决于后续的参考覆盖、对象提取、可学习视觉表示和独立质量评估。
