# CRF：当前不足、目标差距与完整迭代计划

**审阅稿 v1.0 · 2026-11-21（北京时间） · 待 Williams 确认后实施**

本轮只进行只读审计、技术资料核对和计划编制。没有修改 CRF 产品源码、重新部署网站、启动训练或调用付费生成 API。本稿提出的接口、功能、质量标准、数据规模和排期均为待确认方案，不代表已经实现。

审计基线：CRF 0.8，源码提交 `26f9b85a2b25a84ef7afd9ace98a2930e5ab5851`。核对范围包括当前源码、原 0.8 研发计划、实际学习记录、六张发布图、像素与编辑验收、下载与旧案例保留记录。已有测试结果作为历史证据引用，本轮没有重新运行整套测试。

## 01 · 复盘结论与责任

**当前交付与目标之间存在架构和验证方法上的差距，不能靠多改几次提示词、多加几个案例或继续提高版本号解决。**

你的目标是：语言模型理解场景，能按需要搜索和观察参考，提炼可生成的视觉规律，通过可执行的完备表示函数生成高真实感新图；同一表示支持语义编辑、像素检查、空间变化和连续视频；编辑器只是模型操作这套能力的工具。

0.8 当前更准确的定位是：**可重绘的二维高斯观测表示、有限的对象外观编排、独立的参考学习流程，以及一部分局部编辑能力。** 它是有真实内核的工作原型，尚未完成上述完整目标。[E01–E05]

此前推进有四项需要纠正的地方：

1. **把过程完成当成能力完成。** 十轮检索、几十张拟合、模型调用和测试数量说明步骤确实执行过，不能说明模型学会了生成新照片。
2. **把不同性质的结果放在相近语境里。** 原图重建、已有对象组合、参考图调色、新场景生成和导出一致性，必须分开验收。
3. **把离线样例的完整性说得过于接近在线产品能力。** 编辑器确有独立的一键多轮参考学习，但自然语言生成任务尚未自动调用对象学习、质量筛选和生成修复全过程。
4. **在画质门槛未关闭时，交付了新的整合版本。** 原计划已经有高保真、边界和生成盲评要求；实际发布没有全部关闭这些门槛。这是执行和发布规则的问题，不能仅靠再写一份宏大计划避免重演。

因此，下一轮应作为一次完整能力工程：内部允许多次实验；对外交付以整体验收通过为单位。研究关卡失败时交付失败结论与路线调整，不把局部改善包装成目标已达成。

## 02 · 你的目标：按可验收行为重新定义

| 目标 | 用户应当能够做什么 | 成立的证据 |
| --- | --- | --- |
| 语言生成 | 描述一个未预制的场景，得到结构正确、外观可信的新画面 | 冻结的未见提示集、全部输出、独立质量评价 |
| 搜索与学习 | 缺少视觉经验时，系统自行找图、看图、提取并学习 | 真实图像输入、来源、共享参数或函数变化、学习前后对照 |
| 代码原生表达 | 导出程序、函数及声明依赖，换运行环境可重绘 | 独立执行；没有隐藏成图替换；明确权重与参考数据依赖 |
| 语义编辑 | 选择墙、窗、树、苹果等对象，改色、形态、位置、数量、可见性 | 对象身份、合法影响范围、边界与依赖传播、撤销 |
| 像素可控 | 对有参考的任务严格检查误差；对修改检查局部影响 | 完整像素统计、关键边缘、保护区、确定性重绘 |
| 合理空间 | 部件连接、接触、遮挡、投影与反射相互协调 | 关系约束与可观察的多视角/空间验证 |
| 连续视频 | 同一场景生成连续运动，不逐帧漂移或丢失身份 | 完整帧序列、轨迹、时间一致性与遮挡检查 |
| 递归改进 | 能诊断失败，修正参数、程序和管线，保留改进证据 | 固定评价器、候选对照、成本与回滚、失败不伪装成功 |
| 可用产品 | 从一次描述到成图、修改、保存、下载都在编辑器完成 | 实际生产环境与主使用设备上的端到端验收 |
| 连续积累 | 红绿灯、果物、湖景、画作及早期案例持续可用 | 资产、入口、交互和导出回归；能力来源清晰 |

### 三个不能混用的“100%”

- **参考观测的严格复现：**在固定尺寸、解码、色彩与取整规则下，RGB 字节全部相同才可称 100%。必要的观测数据、密集样本或无损残差必须披露。它证明保真，不证明泛化。
- **局部编辑的严格保护：**相对编辑前的规范渲染，预先声明的保护区 RGB 不变。混合边缘与投影等合法影响区另验，不能事后缩小保护区。
- **新场景的质量：**没有唯一目标照片时不存在有意义的“与目标 100% 像素相同”。要检查语义、视觉合理性、可控性和你认可的质量样例。

用户希望的逐像素可控继续保留为设计目标。近似重建门槛不能替代严格复现，严格复现也不能替代新生成能力。

| 新照片生成 | 六图中前三图为对象组合；后三图为编辑/变体 | 没有未见条件的独立生成质量评测 | 通用能力未证明 |
| 视角/视频 | 旧版本保留相应案例与执行器 | 0.8 新格式没有完整相机、深度可见性或时空函数 | 不可借用旧成绩 |

| 重绘与交付 | 共享 JS 渲染器；一个独立重绘案例、一个浏览器导出案例通过 | 生产登录后完整流程与所有包内场景未全量复验 | 部分路径已验证 |
| 旧案例 | 223 个旧文件有保留校验 | 仍需入口、交互、视频与迁移回归 | 保留基础良好 |

以上数字来自现有记录，不是本轮新跑的性能成绩。[E01–E08]

### 离线成绩与在线体验必须分开

发布学习样本采用最长边 512、8,192 高斯和 70 次几何步；浏览器独立学习采用最长边 384、4,096 高斯和 35 步。另一次实际浏览器低预算演示使用 1,024 高斯，显示 PSNR 20.62。不能用离线街景的 43.45 dB 代表用户上传任意图片后的即时效果。[E01、E04、E05]

当前 Node 单次冷渲染约 429/669 ms，不是 Mac mini 或所有浏览器上的帧率承诺。缓存后的编辑、首次载入、完整拟合、模型推理、视频编码应分项计时。

## 05 · 为什么此前迭代总是低于预期

### 5.1 “能表示”与“能生成”之间缺少实际学习机制

0.8 为每张图单独求参数。增加实例文件数量，不会自动形成跨实例共享的生成规律。高斯数、顺序与局部坐标各不相同，直接平均两个文件的系数也没有稳定的语义含义。

新的学习模块必须明确：共享参数是什么、条件如何进入、训练数据与留出数据是什么、损失怎样定义、检查点如何保存、未见条件的结果是否改善。数学公式和 schema 字段不是这项能力的实现证据。

### 5.2 视觉经验的来源没有被解决

代码承担计算过程；自然图像的经验仍需来自数据、学习权重、程序规律或可对应的真实观察。DeepSeek 能描述物体与评价画面，不等于它已经通过 API 对话训练了一个像素生成器。

几十张图适合验证有限类别、固定或窄视角下的变化，或适配已有视觉先验。没有证据支持仅凭几十张散图从零获得通用旗舰生图质量。上一轮对共享函数族的建议应被明确列为研究假设，而不是实施保证。

### 5.3 当前外观已经混合了材质、照明和视角

现有高斯场在编码后的 sRGB 中累加系数，色相与曝光是显示数值变换。它没有独立的材质、法线、光源、反射和投影变量。各物体带着原照片的高光、阴影和视角进入新场景，拼贴感因而不能靠位置微调彻底消除。

### 5.4 对象边界与结构关系没有得到同等重视

alpha 覆盖率单独保存，RGB 高斯拟合不会自动修正错误蒙版或被背景污染的边缘。支架连接立柱、物体接触平面、投影附属于物体等关系，当前主要靠坐标安排，没有可传播的约束。

### 5.5 验收偏向“程序没有坏”，没有充分验证“结果达到目标”

工程测试、输出哈希、像素保护与模型自评都有价值，但它们不等于真实感。像素保护甚至可能绕开最困难的混合边缘。高保真门槛未通过时发布，更使用户感知到的版本进步与核心目标脱节。

### 5.6 管线与发布单位不匹配

跨脚本、人工修正得到的样例可以展示研究进展，却不能代表用户进入编辑器后会自动得到同样结果。下一版必须把“同一用户任务能够重复完成”作为交付单位。

## 06 · 目标分层：完整规划，但不虚构已解决的研究问题

### 北极星：通用、可编辑、代码执行的视觉生成

任意合理场景的高真实感图像、多视角与视频，均由语义可操作的函数系统生成，具备明确来源、可重绘性及持续改进机制。现阶段不能给出有依据的完成百分比或保证日期。

### 下一次对外交付：一次完整的 CRF 0.9 候选能力包

拟议范围：

1. 一次自然语言任务自动串联能力缺口识别、参考学习、函数获取、生成、渲染、检验和有限修复。
2. 建筑街景、自然风景、物品静物三类中，完成冻结测试；每类能力单独标注，任一类未通过不能宣称三类完成。
3. 提供至少 10 张预先选定测试任务的 1K 级新生成作品，并公开完整测试画廊与失败分布。它们必须包含新布局和新外观，而不仅是调色或整图重放。
4. 原红绿灯案例完成换色、移位、删除、背景补齐和撤销；新类别也支持对应的语义编辑。
5. 同一新表示交付 3 段 5 秒、24 FPS 的视频，以及声明相机范围的三视角结果。单图条件下的推断区域显式记录；有多视角真值的任务另验真实性。
6. 旧案例全部保留，生产登录后操作、实际下载、保存重载与独立重绘通过。
7. 参数、程序与管线层反馈可以自动运行；算法自修改作为受控实验候选，不允许修改验收规则后自行宣布成功。

这些是**拟议发布条件**，不是对所有研究风险的成功保证。若生成路线验证失败，就停止发布候选，回到路线审查；不能删减关键条件后沿用“完整达标”的名称。

## 07 · 完整技术架构

### 7.1 三种职责，接入同一个可执行表示

**DeepSeek 语义规划器**解释目标、搜索缺口、对象关系与保持条件；**视觉函数生成器**产生新的外观/结构参数；**数值优化器**在预算内修复可量化误差。三者共同操作版本化场景，最终由 CRF 渲染器求像素。

拟议统一状态包括：

- 对象与部件的稳定身份、类别、规范坐标、可变形参数。
- 高斯颜色/特征块、覆盖率、边界混合与精度层级。
- 材质、照明、深度/法线的可用估计及不确定性。
- 连接、接触、遮挡、投影归属、反射依赖等关系。
- 相机/时间条件、可见区、未观察区和新显露区域。
- observed / inferred / generated / learned 来源；训练或观测依赖。
- 渲染器与解码器版本、种子、资源预算、质量状态、修订记录。

旧 sRGB 高斯资产的数学含义保持不变。若新管线采用线性光照或神经特征，必须使用不同的表示版本和适配器，不能重新解释旧系数而破坏原图。

### 7.2 一次用户任务的完整闭环

自然语言目标 → 语义约束与缺口 → 参考检索/观察 → 分割与规范化 → 拟合或共享学习 → 质量准入 → 条件生成 → 共同场景求解 → 高斯渲染 → 独立评价 → 定位失败模块 → 有界修复/回滚 → 可编辑工程与文件交付。

系统保存任务 ID、阶段状态、实际依赖、当前候选、最佳已验证候选、成本和中断点。生成缺少资产时，能够进入学习，再恢复同一生成任务。预览拟合与最终质量拟合分别标记。

重型训练与拟合由独立执行器承担，浏览器主要负责可视化、快速编辑与任务控制。是否使用本地、服务器 CPU 或 GPU，由资源探针决定，不把浏览器低预算结果标成最终质量。

### 7.3 共享函数生成的数学目标

当前是逐图求解 `theta_i = Fit(image_i)`；目标是学习共享参数 `phi`，由 `theta = G_phi(semantic_conditions, variation_seed)` 生成新的函数，再运行 `image = Render(theta)`。

实现上必须先解决规范坐标、部件对应与参数集合顺序问题，再比较结构模板、共享统计与学习型条件解码器。禁止直接平均不对应的高斯数组后称为类别学习。

### 7.4 先支持有限、可检验的共同成像

第一阶段选择粗糙墙面、一般不透明物体与相对简单的光照。将基础色/纹理、明暗、边界覆盖率与接触/投影分开建模；从线性颜色约定开始定义，而不把 sRGB 乘法当作物理重照明。

单张图不能唯一决定真实材质与光照。估计值必须标注置信度；镜面、透明、复杂互反射属于独立能力，不因普通墙面成功就默认支持。[R04]

### 7.5 深度与时空是增强，不是直接替代生成

Depth Pro 2 可评估为图像/视频深度的辅助来源。深度有助于遮挡、分层视差与运动一致性，但不提供被遮挡物体的真实外观。当前 0.8 没有集成其权重。[E01、R05]

新视角应区分二维画面变换、估计深度视差和经真实多视角验证的结果。连续视频由共享对象状态和轨迹生成，新增区域由明确的推断模块处理；不以逐帧重生成或全图平移冒充一致世界状态。

## 08 · 技术路线选择与转向条件

| 路线 | 实现内容 | 价值 | 主要风险 | 本稿建议 |
| --- | --- | --- | --- | --- |
| A：显式结构＋直接 RGB 高斯 | 规范部件、共享外观统计/条件模型，输出可直接渲染的 RGB 高斯 | 最接近原生、显式与局部编辑要求 | 跨类别细节与复杂语义可能受限 | 主线；首先验证 |
| B：可学习视觉特征＋高斯空间组织 | 使用声明的视觉编码器/条件模块，生成空间与纹理特征，必要时经可导出的解码器求 RGB | 可以利用更强的视觉先验 | 对象控制可能弱化；运行依赖更多；并非纯 RGB 高斯 | 并行可行性支线；不可静默替代 A |
| C：外部成品图再拟合 | 调用现成图片生成器输出完整图片，再转成高斯 | 可以快速得到好看样图 | 只证明转码/重建，未解决本项目的生成机制 | 可作外部质量对照，不作为主线完成 |

**推荐审阅口径：**允许学习型视觉模块、明确披露的预训练编码器、分割与深度先验；最终作品必须有可导出、可语义操作的程序与依赖。使用神经解码器时如实标注，不能继续称作纯 RGB 高斯求值。不得以路线 C 的成图包装成 CRF 已获得原生生成能力。

视觉编码器提供特征与约束，本身不等于一个可采样的新图像分布。若 B 需要预训练生成器，必须明确具体模型、训练来源、生成对象、解码方式，以及是否采用扩散/流匹配等机制。完整 RGB 成图再转高斯仍归入 C，不能因为最后用了高斯就改称 B。

初期同时比较两个有效假设：A1“程序结构＋共享外观统计”和 A2“共享条件模型输出高斯参数”；B 仅在可用权重、编辑性和运行代价可核验后进入对照。

相关研究只能作为候选依据：GaussianImage 支持表示/压缩；GPSToken 采用高斯空间参数与纹理特征，并经学习解码器重建，公开生成路径为类别条件；GaussianDiffusion 的直接高斯生成展示集中在小型数据，其完整量化评价尚不充分。没有一项现成证据能保证接入后满足本项目全部要求。[R01–R03]

## 09 · 数据与十轮学习计划

### 9.1 四类数据分开管理

| 数据 | 目的 | 不可混用的地方 |
| --- | --- | --- |
| 固定重建/边界集 | 检查拟合、覆盖率、局部像素误差 | 不能作为新生成质量的替代 |
| 同类别不同实例 | 学习共享结构、外观分布与条件变化 | 文件数量不等于独立实例数量 |
| 同场景多视角/多光照/视频 | 约束空间、材质、照明与时间 | 不相关网络图片不能当成同一场景 |
| 留出条件与终测数据 | 检查泛化、指令与稳健性 | 不得进入训练、拟合、检索目录或调试反馈 |

数据先按实际场景、拍摄序列、主体与近重复关系分组，再划分训练/验证/终测。建议初始比例 60%/20%/20%，按类别检查覆盖，不因比例整齐而制造泄漏。

### 9.2 十轮是带问题的学习周期

| 轮次 | 主要工作 | 必须留下的结果 |
| --- | --- | --- |
| 1 | 定义类别、可控条件与样本标准 | 覆盖矩阵、来源与排除条件 |
| 2 | 收集布局和部件变化 | 结构标签与实例关系 |
| 3 | 收集材质与细节变化 | 材质/纹理样本及拍摄条件 |
| 4 | 收集光照差异 | 可对应照明记录；未知条件明确标注 |
| 5 | 收集边缘、连接、接触与遮挡 | 局部裁切、alpha 审核与关系标注 |
| 6 | 首轮提取、拟合与共享学习 | 单图误差、共享检查点与失败类型 |
| 7 | 根据开发集失败补查 | 每张新增图对应的能力缺口 |
| 8 | 修正提取/对应/条件表达 | 新旧流程对照，人工辅助记录 |
| 9 | 冻结候选后做开发验证 | 预算一致的结果与路线选择 |
| 10 | 汇总有效样本与验证结果 | 学习前后变化；未完成项；是否进入下一周期 |

终测集在开发前独立封存，不把第十轮改成“用终测失败继续训练”。正式终测失败后，新一轮开发需要新的独立终测保留集。

### 9.3 计划规模与边界

下一阶段拟对三类各准备约 40–100 张有效参考，形成约 120–300 张的受控资料集；这是采集/适配的初步工作量，不是足以从零训练通用模型的声明。每个新类别的初始学习批次按至少十轮组织，轮次内真实下载量按来源与预算决定，质量不合格的图不计入可学习样本。

普通生成与编辑复用已验证的函数和权重；只有能力缺口触发补学时，才启动有预算的追加周期。十轮不是每次推理的最低开销。封闭条件下的生成终测冻结学习状态，不随某条终测指令继续训练；允许实时检索学习的产品任务单独统计为参考条件任务。

先用少量样本做可行性探针，再按缺口扩展。若泛化学习需要更大数据、更多权重或 GPU，进入独立研究预算，不暗中扩大调用量。现有 42 份数据保留，重新检查实例独立性与适用性后使用。

## 10 · 工作包、依赖与阶段出口

### P0 · 冻结目标、基线与资源

**产物：**目标能力表、6–12 张质量锚点、旧案例清单、冻结任务与评估配置、设备/算力探针计划、成本上限。

任务：把你认可的照片真实感落实为实际样张；核实参考模型/产品的准确版本与生成设置。无法取得可核验输出时，使用你认可的样张作绝对标准，不拿一个模型名称代替成绩。固定原街景和关键 ROI；生成任务与重建任务分开。目标本地设备建议包含你的 Mac mini M4/16GB，实际性能待测。

**出口：**目标与评价口径可执行；无未声明的资产或模型依赖；旧案例可追溯。此阶段不能以“代码已写”取代目标冻结。

### P1 · 任务骨架、完整编排与质量准入

**产物：**一个持久化任务状态机，贯通搜索、观察、对象提取、拟合、入库、生成、渲染和修复。

任务：连接目前分开的学习与生成入口；资产缺失自动转入学习；新增对象提取；拒绝不合格对象自动入库；预览与最终质量分级；进度、取消、重试、断点续跑和错误原因清晰。任何阶段失败保留已有工程。

**投入顺序：**P3 之前只做 P1a，即实验必需的任务协议、日志、预算、失败状态和资产接口，复用现有能力做最小贯通。P3 通过后再做 P1b，扩展完整对象学习、质量修复、恢复与产品体验，并与 P4/P6 整合。避免先完成大型工作台，再发现生成机制不成立。

**出口：**一条未预制语义任务可从缺少资产开始走到可编辑结果，阶段之间无需人工复制文件或改代码。不能把仅新增一个整图观测函数判为对象学习完成。

### P2 · 表示、边界与关系基础

**产物：**版本化 CRF 状态、独立覆盖率/前景边缘处理、连接与接触关系、CPU 规范渲染器及必要的加速实现。

任务：明确旧/新色彩含义；规范部件坐标；边缘混合色估计；多尺度细节；关系依赖传播；删除后的背景推断；严格复现模式和近似生成模式分别保存来源与成本。

**出口：**原街景高保真与边界任务达到冻结门槛；新增案例不依赖逐例修补坐标；编辑与撤销确定性通过。

### P3 · 生成机制可行性闸门

**产物：**至少两种机制的可运行对照、实际共享参数/检查点、未见条件的完整输出和路线选择结论。

任务：先在建筑立面类建立规范对应；比较 0.8 重组、共享统计、条件生成器，必要时加 B 路线。验证新布局、新外观与条件变化；检查训练参数是否真的影响留出结果；同时观察记忆和最近邻依赖。

**出口：**至少一条路线在固定预算下，未见条件的语义与质量同时改善，且不存在严重复制或不可编辑退化。仅改善训练集或原图拟合时判定失败。先最多三轮有明确假设的研究实验；无有效改善就返回路线决策，不继续做展示图掩盖问题。

### P4 · 共同成像与跨类别扩展

**产物：**共同布局、照明、边界、接触/投影约束，以及三类的独立能力报告。

任务：在通过 P3 的生成器上学习有限的材质/照明分离；处理对象之间的接触和依赖；扩展自然风景与物品。自然场景中的水面反射、远近层次和植被尺度应作为结构问题，不仅是纹理问题。画作只验证笔触、结构与可编辑表达。

**出口：**三类都通过预定新生成与编辑任务；失败类别不借用其他类别的成绩。未过关时继续内部实验，不降为少数最好样图后发布。

### P5 · 时间与空间扩展

**产物：**统一状态的轨迹、三视角结果、三段 5 秒视频和逐帧验收。

任务：评估深度/法线辅助；相机变化范围可声明；持续对象身份与遮挡；新显露区域的推断；保证同一随机纹理跨帧一致。对有真实相邻视角的数据计算误差，对未知内容标注不确定。

**出口：**至少 120 帧/段，固定输出规格，运动符合轨迹，结构/纹理无严重漂移，推断区域没有空洞。不能以成功编码 MP4 或静止帧差很小判定通过。

### P6 · 编辑器整合、生产与交付

**产物：**可用的整合编辑器、完整工程包、至少 10 张固定展示任务输出、全部评测画廊、模型/数据依赖及复现命令。

任务：自然语言→生成→修改→撤销→保存→重载→下载→独立重绘全流程；生产登录后实际验收；所有旧入口与操作回归；依赖按需载入；失败与超预算可见；包内每个发布场景逐一重绘。

**出口：**画质、泛化、编辑、时空与使用门槛全部关闭。未通过不发布为“达到目标”的版本。保留上一可用版与完整回滚。

### 贯穿工作包 P7 · 反馈、递归改进与证据

| 层级 | 可以改进什么 | 验证与限制 |
| --- | --- | --- |
| L0 参数 | 高斯位置、尺度、颜色、覆盖率等 | 固定目标、保留较优检查点，数值误差与关键 ROI 不退化 |
| L1 场景程序 | 对象、布局、关系、条件 | 语义约束、合法影响范围、独立画面检查 |
| L2 管线 | 检索、分割、拟合、补全与生成器选择 | 依据失败类型调度，固定预算，不能跳过质量检查 |
| L3 算法候选 | 学习规则或局部实现 | 在隔离分支验证回归与留出集；禁止自改验收器；效果成立后纳入整合 |

每次候选记录父版本、实际输入、程序、权重/函数版本、渲染结果、指标、成本与接受/拒绝理由。研究失败与资源耗尽是合法结局，不能无限重试直到选到一张好图。

## 11 · 拟议验收合同

以下数值是待确认的工程目标，不是行业通用标准，也不是当前成绩。确认后在开发开始前冻结；如需改变，必须作为范围变更记录，不能根据终测成绩事后调低。

### G0 · 目标、数据与依赖

- 6–12 张你认可的质量锚点；如对比某旗舰模型，应保存准确产品/版本、任务、设置与实际输出。
- 重建、语义新生成、编辑、推断视角四种任务分别标记。
- 数据按场景/实例/拍摄组留出；感知近重复审查；终测无数据泄漏。
- 保留所有旧案例；所有来源、权重和表示类型可追溯。

### G1 · 重建与数值保真

- 固定 12 张重建集：街景/建筑 4 张（含原图）、自然 4 张、物品 2 张、画作 2 张。按原生规范化尺寸评估，报告尺寸与所有预处理。
- 近似高保真轨道延续 PSNR ≥38 dB 且 SSIM ≥0.98；逐张报告，正式验收集应全部通过，失败不能被平均值掩盖。
- 固定边缘带的拟议 RGB8 MAE ≤4（归一化 ≤4/255）；记录最大误差、误差分位数、最差区域及高倍裁切。颜色误差统一在解码后的规范 sRGB RGB8 上计算；SSIM 窗口与边界处理在 P0 冻结。
- 严格参考复现轨道要求规范输出 RGB 100% 相同；如果使用观测编码或无损信息，公开数据量和机制，不计为生成能力。
- 参数总量、alpha/索引/残差/模型权重、文件体积、时间与内存均入账。预算增长可以成为研究选择，但不得写成同预算算法改进。

### G2 · 新生成质量与泛化

- 可行性阶段：12 条开发留出描述 ×2 个种子，对照机制；用于路线选择，不用于最终能力宣称。
- 整合终测：三类各 20 条未用于调试的描述，合计 60 条 ×3 个固定种子，共 180 个评测任务/路线。一个“提示×种子”是一个任务，每任务最多三个候选、两次质量反馈，最终选择规则在终测前冻结。分别报告首次输出、最终输出和全部候选；超时、空图、结构失败、预算耗尽都保留在任务分母中。180 是最终任务数，不是全部候选图数量。
- 对象数量、类别、相对位置、指定颜色等可客观判断的原子条件满足率拟定 ≥95%，整条指令全满足率 ≥90%。原子条件及重要性在运行前冻结；关键数量、身份或指定关系错误，不能计为整条通过。
- 对比 0.8，在真实感盲评中拟定偏好率 ≥65%，按提示为聚类单位给出置信区间，下界应高于 50%。这只是相对改善门槛。
- 绝对质量另验：参照质量锚点，拟定 ≥80% 输出达到“整体像同一环境拍摄、无明显拼贴、仅少量局部瑕疵”的 4/5 等级；严重漂浮、断裂、重复部件、光照冲突或大片彩边的失败率 ≤5%。
- 上述语义、绝对质量、相对改善与严重失败率要求三类分别通过，不以总体均值抵消某一类失败。参考条件生成与无特定参考的语义生成分别统计。
- 预先选定的 10 张发布展示任务均需通过语义和绝对质量要求；不能从 180 张中事后挑最好的十张来替代通过率。
- 真实感评价采用盲化任务顺序与统一量表。独立人工评审优先；若仅有模型评审，明确列为辅助结果，不声称已完成人类质量验收。用户对锚点与最终样张拥有最终判断。
- 分别报告参考条件生成与无特定参考的语义生成；训练期图像、权重和规则来源明示。近邻检查用于发现明显复制，不能独自证明泛化。

### G3 · 编辑、边缘与背景补全

- 每次编辑执行前声明对象、允许影响区、边界带与依赖区域。纯局部外观编辑的保护区要求相对规范基线 RGB 0 变化；移动/改光允许已声明投影、反射等关联区域变化。
- 使用具有独立前景、背景和 alpha 的合成真值，加上自然照片人工审核。专测 1–5 像素混合边缘，不能只测 alpha=1 的内部。
- 边缘检查颜色污染、双轮廓、断裂和抗锯齿；拟议合成边缘 RGB8 MAE ≤4（归一化 ≤4/255），关键连接偏移 ≤1 像素（在冻结分辨率下）。
- 有干净背景的受控遮挡测试覆盖亮墙、暗墙、墙缝和阴影边界。背景真值只交给评估器，不能由任何可逆函数/缓存泄漏给补全器。
- 拟议平滑背景 RGB8 MAE ≤5、SSIM ≥0.95；结构区域 RGB8 MAE ≤8、已知墙缝偏移 ≤1 像素。补全误差只在预先冻结的隐藏区域计算，边界带和结构线单独报告，不能加入未改背景稀释误差。评价蒙版由独立真值生成，数据在合成遮挡前按场景划分，避免干净背景通过另一种形式进入训练或函数资产。实际自然图隐藏区只评连续性与合理性，不报真实恢复百分比。
- 至少 20 条完整编辑序列，覆盖换色→移动/形态变化→删除→撤销→保存重载；身份、依赖与输出可复现。

### G4 · 视频与空间

- 交付 3 段 5 秒 ×24 FPS，共 360 帧；拟议最终规格 1080p，调试预览可低分辨率但不得替代终验。每段保存轨迹与可重绘工程。
- 同场景三视角包含正面和左右小幅变化；具体范围由观测支持决定并在生成前声明。没有观察依据的内容标为推断。
- 轨迹、位移或角度必须在生成前冻结，并产生实际可见的空间差异。数据不支持时判定能力范围不足，不能自动缩成近乎不动来过关。
- 有真实多视角/视频参考时，使用独立标定或预先固定的配准规则，计算图像误差、深度边界、可见性和跟踪稳定性；不允许通过任意非刚性形变消除生成错误。遮挡排除由真值或固定规则决定，不能由待测结果自行屏蔽困难区域。无真值时做连续性检查，不声称真实世界恢复。
- 检查全部帧和固定局部跟踪，不能只看首尾帧。光流/跟踪误差需排除遮挡变化；静止视频不能通过运动任务。
- 不允许明显的对象身份变化、结构跳变、纹理游动、曝光突变、空洞和接触破坏。量化时间门槛在 P0 的真实序列基线上校准并冻结。

### G5 · 实际使用与可重绘

- 生产登录后对预先指定的至少 10 个完整任务逐一验收，包含从资产缺失开始的学习生成、编辑、保存重开、PNG/视频/工程下载。所有尝试和失败均记录，不能从大量运行中挑十次成功；无人工代码修补才能计为端到端成功。这组开放参考任务与 G2 的冻结学习终测分开统计。
- 原有案例逐入口回归，不能只验文件哈希。新增发布工程全部在独立环境重绘，不再只抽验一个。
- 浏览器首屏应显示明确状态，不能持续空白；冷加载、首次预览、最终出图分别统计 p50/p95。
- 拟议交互目标：1K 级场景、已载入资产的常规属性编辑 p95 ≤250 ms；最终质量导出另计。该目标需在主使用设备实测，不能借用服务器单次计时。
- 生成/学习任务可取消、可恢复；预算耗尽明确停止。下载验证实际字节、文件完整性、图片尺寸、视频时长/帧数与工程依赖。
- 同规范 CPU 路径要求像素确定性；若 GPU 浮点产生差异，预览容差与正式精确导出分别定义，不能混为同一种 100%。

## 12 · 反馈的停止与转向规则

| 观察到的问题 | 判定 | 下一步动作 |
| --- | --- | --- |
| 只改善原图拟合，未见条件没有改善 | 生成机制尚未成立 | 调整共享表示/训练目标，停止扩充展示 |
| 图库扩大但输出更依赖最近参考 | 记忆增长，泛化证据不足 | 检查对应关系与条件模型，必要时引入声明的视觉先验 |
| 局部纹理清晰，整体仍漂浮/拼贴 | 共同成像约束不足 | 修接触、透视、光照与依赖；不继续仅堆高斯 |
| 改色内部正常，混合边缘污染 | alpha/前景估计失败 | 专项边缘求解与独立真值测试 |
| 删除无透明洞，但墙缝或阴影断裂 | 补全结构不成立 | 增加背景结构模型和受控遮挡实验 |
| 只有离线样图好，在线流程不能复现 | 工程闭环未完成 | 接通任务与执行器；不以离线成绩代替产品验收 |
| 只有单类别通过 | 范围有限 | 明确能力标签；继续扩展，不称通用生成 |
| 只有外部成品图转码才好看 | 核心生成问题尚未解决 | 单独报告路线 C，不混入原生生成成绩 |
| 超出数据/算力/调用预算仍失败 | 本轮假设或资源不足 | 冻结证据，提出扩预算/改路线/缩研究范围的具体选择 |
| 自评上升但独立评价下降 | 评价被优化偏 | 保留独立门槛，调整优化目标；禁止改评分规则制造成功 |

## 13 · 排期、算力与预算

### 13.2 先测量再冻结资源上限

- **本地交互端：**建议 Mac mini M4/16GB + 用户常用浏览器；未实测前不承诺帧率。
- **训练/拟合执行端：**CPU 或 GPU 独立任务；根据候选模型真实显存、速度与可用权重选择。没有证据时不默认已有云 GPU 或预算。
- **语义 API：**记录搜索、真实看图、生成、评阅、修正分别的调用量与 token。每个任务设候选和反馈上限，不能无限增加思考轮数。
- **可行性默认上限：**每种路线最多三轮有记录的假设实验；每个生成任务最多三个候选、两次质量反馈。正式终测维持固定预算。
- **费用：**由实际 API token/工具费用、GPU 小时、存储与流量组成。当前不写未经核验的价格或总额；P0 提供实测单位成本与总量估算后冻结。

本稿的确认授权后续按选定范围进入研发；不自动视为批准未明确的付费扩容。需要扩大资源时，提供已完成结果、失败原因、具体新增预算与预期收益，避免让用户反复确认没有实物的空泛下一步。

## 14 · 用户实际会收到什么

最终候选必须同时提供：

1. 在线 CRF 图形计算编辑器，旧案例完整保留。
2. 10 张预先指定任务的 1K 级新生成作品，及完整 180 图/路线终测结果与失败分布。
3. 原街景和新类别的语义编辑工程、边缘裁切、保护区与受控补全报告。
4. 三段 5 秒视频、三视角结果、轨迹与观察/推断标记。
5. 可重绘工程包：场景程序、函数参数、共享模型或声明依赖、版本、种子、来源和运行命令。
6. 全量验收表：每个门槛通过/未通过/未测，不能只给一份总 pass。
7. 资源与运行报告：用户设备体验、每图/每视频成本、时间、内存、模型调用与失败恢复。
8. 另一 LLM 的接入说明：如何从语义条件生成/修改 CRF，以及哪些能力尚不支持。

内部实验以实验编号记录。只有整体合同满足，才向用户交付新版本。若未满足，交付真实研究结果与待决策项，保留现有可用版本。

## 15 · 本次需要审阅的决定

### D1 · 是否接受这一完整交付范围

推荐：采用 P0–P7 的完整能力计划，三类静态图像、语义编辑、自动学习闭环、有限多视角/视频和生产可用性均保留。内部按闸门推进，对外不再为每个局部改动单独发布“达标版本”。

### D2 · 可学习模块的边界

推荐：允许明确披露的视觉编码器、分割/深度先验与学习型条件生成器；坚持语义对象可控、程序可导出、依赖可重绘。纯 RGB 高斯与神经特征解码分开标记。外部完整图片生成再拟合只作为对照或另行认可的路线。

如需预训练生成先验，其具体模型与生成机制必须先写入方案；编码器不等于生成器，图像生成后转码不等于原生函数生成。

### D3 · 质量锚点与严格复现

推荐：使用你认可的实际样张冻结照片真实感；严格原图 100% 单列，不允许以它替代新生成能力。缺少可核验参考模型输出时，不宣称达到某个模型水平。P0 可以先整理候选锚点供审阅。

### D4 · 资源与研究失败

推荐：先做有限预算的路线验证。没有有效提升时暂停扩大开发，给出证据和具体转向建议；不通过降低门槛、隐藏失败或增加展示页来“完成版本”。具体费用上限在资源实测后确认。

**本轮停在审阅。你确认方案与需要调整的范围后，才开始新的产品迭代。**

### 一手研究（2026-11-21 查阅）

- **R01 — GaussianImage：**二维高斯图像表示与压缩，支持表示方向；不等于任意文本生成能力。论文：[ECVA 官方页面](https://www.ecva.net/papers/eccv_2024/papers_ECCV/html/1421_ECCV_2024_paper.php)。
- **R02 — GPSToken：**空间高斯参数与纹理特征结合，经学习解码器重建；公开生成说明为类别条件。权重、依赖和实际编辑能力仍需运行核验，不能直接认定为 CRF 替代品。[论文](https://arxiv.org/abs/2509.01109)；[作者代码](https://github.com/xtudbxk/GPSToken)。
- **R03 — GaussianDiffusion：**直接在二维高斯集合中学习生成的研究原型；小型数据实验不证明通用照片质量，项目说明完整量化评价尚待发布。[作者代码与状态](https://github.com/simoncoessens/GaussianDiffusion)。
- **R04 — 本征图像分解：**材质与明暗分离需要专门约束与学习，单张图存在歧义。[CVPR 2020 官方论文页](https://openaccess.thecvf.com/content_CVPR_2020/html/Liu_Unsupervised_Learning_for_Intrinsic_Image_Decomposition_From_a_Single_Image_CVPR_2020_paper.html)。
- **R05 — Depth Pro 2：**图像/视频深度辅助候选；不能替代隐藏外观生成。[Apple 项目页](https://apple-aiml-research.github.io/ml-depth-pro-2/)。

上述研究提供机制与风险参考；本稿没有下载运行其权重，也没有将论文指标与 CRF 指标直接比较。
