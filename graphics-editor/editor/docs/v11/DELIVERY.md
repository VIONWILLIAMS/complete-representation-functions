## 1. 技术判断与升级方向

CRF 的可积累资产应当是**可调用、可组合、可检查、可重放的对象函数及其使用经验**。更强的语言模型可以改善场景编排，但项目仍然需要明确的像素语义、真实参考与来源、版本化函数库、局部编辑、计算预算和用户反馈。

这次将三个原始层次接到同一种工程表示上，并增加对象函数学习这一能力：

| 层次 | 本次实现 | 积累的项目资产 |
|---|---|---|
| GUI Service | 参考导入/检索、裁剪与覆盖、参数与 Scene IR 编辑、反馈、图片和视频导出。 | 与具体场景、函数版本及输出帧绑定的操作和反馈。 |
| Agent Harness | 固定任务输入、轻量函数目录、模型场景提议、作用域/预算检查、真实渲染与运行记录。 | 可核对的请求、失败、用量和候选结果；模型更换时仍保留工程契约。 |
| Compute Kernel | 同一 CPU 内核解释显式、高斯、神经函数；联合采样、线性颜色合成、直接/缓存两条路径。 | 可复用的执行语义、近似误差记录和内容版本缓存。 |
| 本地对象函数学习 | 从真实图片训练小型坐标网络；保存权重、覆盖、来源、数据摘要和训练报告。 | 有明确适用范围和不可变版本的视觉函数。 |

这里的计算优化作用于应用执行和任务组织。它没有修改托管 LLM 的注意力算子、KV cache 或权重。减少完整权重进入上下文、避免每次修改都调用 LLM、复用已计算函数场，可以分别减少上下文负担、调用次数和数值计算量；具体的 LLM 成本与成功率仍需要真实供应商任务集测量。

工程闭环为：**真实参考 → 训练/显式建模 → 固定函数版本 → 人工或 LLM 编写 Scene IR → 内核求值 → 图片/二维视频 → 绑定输出的反馈**。本分支保存反馈，尚未实现从这些反馈自动学习语义偏好、生成新算子或自主晋升内核。

## 2. 已实现的核心设计

### 2.1 单一工程与固定函数版本

`crf.project.v1.1` 保存函数注册表、Scene IR、参考元数据、数据集记录、训练运行、反馈和历史。每个函数使用内容 SHA-256 作为精确版本；场景引用该版本，不能用模糊的 latest 替换已验证内容。

Scene IR 的对象包含函数引用、实例编号、位置、大小、旋转、颜色乘子、不透明度、层次、可见性及显式二维运动。GUI 参数编辑与代码编辑通过同一 Patch 机制提交。陈旧的代码草稿、无效引用、NaN、非法尺寸和越界编辑不会成为有效场景。

函数注册支持显式场、既有二维高斯适配和小型神经外观。不同模式共享覆盖及合成语义。覆盖来源独立声明，可以是矩形、人工形状或固定 alpha；学习到颜色不等于自动完成对象分割。

### 2.2 真实训练与可重放函数

训练器使用 Fourier 坐标特征、有限实例 one-hot、两层 tanh 隐层、三通道 sigmoid 输出和 Adam 优化。默认单实例 hidden=24，共 **1,059 个参数**。训练在线性 RGB 中进行，真实记录 loss、实际步数、数据摘要和最佳检查点。

训练参考的 RGB 仅用于预览、裁剪和训练。渲染依赖是已保存的程序、权重与覆盖，不重新读取参考图，也不把原 RGB 图层贴回场景。权重能够编码参考图信息，因此仍然保存来源和重建范围，不能把它称为无学习权重的纯解析模型。

多参考模式共享解码器，通过实例编号选择已学实例。它提供有限实例重建；未知对象采样、材质分解和语义条件控制尚未由本次实验建立。

### 2.3 同一内核上的计算优化

直接路径在采样点求值函数。缓存路径先由函数本身生成规范坐标网格，再进行双线性求值。缓存键包含固定函数版本、实例与配置，属于有误差的数值近似。

RGB 与 alpha 在相同子像素位置计算，在线性空间预乘合成后输出 sRGB。编译、缓存构建、求值次数、估算 MAC、内存与实际时间分别进入诊断。对象包围范围减少无关区域访问，硬预算拒绝无法承担的直接计算配置。

当前实现为 **CPU JavaScript 与 Worker**。没有启用 WebGPU，没有承诺所有场景实时，也没有把开发者编写的优化记作系统自主 RSI。

### 2.4 Harness 和模型适配器

模型收到轻量函数目录、当前场景和任务目标，目录包含固定版本、实例、尺寸和允许控制，不包含大数组权重。当前 HTTP 适配器返回完整 Scene IR 或能力不支持的原因；本地 Patch 是统一编辑与提交机制。

一次编排只有一个 API 操作，正常一次供应商请求，最多增加一次结构修复请求。模型输出需通过结构、引用和编辑范围检查，再实际渲染。渲染结果绑定场景摘要、函数版本、帧配置与输出字节摘要。成功状态仍是需要审阅，模型自评不会升级为视觉验收或形式证明。

取消、请求期间的工程修改、渲染回调改变候选、未知用量和失败调用均有明确处理与记录。没有供应商凭证时，自然语言按钮禁用，本地训练、代码编辑和导出可继续使用。

## 4. 固定计算基准与误差约束

[计算报告](../../reports/v11/compute_benchmark.json) 在测量前固定了输入与阈值：Linux x64、AMD EPYC、Node v24.22.3；256×160 单对象、单采样、cache64；五次重复取中位数；全帧 RGB8 MAE≤1、最大通道误差≤12、alpha 字节一致。[摘要核对](../../reports/v11/benchmark_integrity.json) 确认报告绑定的源码、模型与输入数据摘要匹配。

| 案例 | Direct 热帧 ms | Cached 热帧 ms | 热帧比值 | 含编译冷启动比值 | RGB8 MAE | 最大误差 |
|---|---:|---:|---:|---:|---:|---:|
| 水面 | 67.199 | 13.691 | 4.91× | 2.63× | 0.15507 | 11 |
| 陶瓷 | 52.226 | 6.006 | 8.70× | 2.72× | 0.09591 | 11 |
| 条件陶瓷 | 54.377 | 6.239 | 8.72× | 2.34× | 0.08783 | 4 |
| 条件橙子 | 53.910 | 6.243 | 8.64× | 2.76× | 0.09388 | 3 |

四例均满足预先固定的数值条件。冷启动包含新 runtime 编译，不是新操作系统进程；编译、冷帧与合计的中位数分别计算。缓存场每个实例为 49,152 字节。

水面三 seed（11/29/47）均完成 600 步并降低训练与空间验证误差。最终训练 MSE 分别为 0.002869 / 0.002506 / 0.002614；空间验证为 0.003778 / 0.005065 / 0.003416。空间验证参与最佳检查点选择，不能作为独立来源测试集。

命令行训练用 96 px 最长边和固定最近邻采样，GUI 使用浏览器 Canvas 重采样及 128 px 上限。因此两条真实流程的输入像素、loss 和权重不同。原三份训练报告记录模型与数据摘要，没有源码 SHA 字段；后补的 integrity 关联明确保留这一事实，未冒充当时已有源码绑定。

这些性能数据不适用于直接推算 640×480 浏览器帧率、Mac mini M4、GPU 或视频编码速度。语言模型实际 token 成本、视觉任务成功率和端到端质量没有在本环境中做真实供应商测量。

## 6. 启动和复现实验

需要 Node.js 22 或以上。从仓库根目录运行：

```bash
git switch feat/crf-1.1-learnable-object-functions
cd graphics-editor/editor
npm ci
npm run dev:v11
```

打开 `http://127.0.0.1:4173/studio11.html`。macOS 可运行 `graphics-editor/Start_CRF_1_1.command`，Windows 使用相邻 `.cmd`。这些启动器已提供；本次没有在用户的 Mac M4 或 Windows 设备上做实机验证。

通过“打开工程”选择 `editor/reports/v11/browser/water-scene.crf.json` 可以直接重放本次结果。选择“湖水样本 → 开始本地训练 → 添加到场景”可重新走真实学习流程。

```bash
npm run train:v11
npm run benchmark:v11
npm run test:v11
npm run build
```

自然语言场景编排需要在本机服务进程配置 `DEEPSEEK_API_KEY`。本环境没有有效供应商凭证，故只验证了适配器和调用/失败/范围边界，没有真实模型任务成功记录。密钥不属于工程和提交内容。
