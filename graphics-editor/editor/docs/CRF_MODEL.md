# CRF Street 0.4：从像素观测到可编辑函数组

## 本版要证明的具体命题

给定这张 667×1000 的 RGB8 照片，建立一个程序表示，使每一个观测像素都有明确的颜色系数、对象归属与投影规则。在原视角逐像素验收，在编辑后分别检查局部变化、关系约束、图像输出和时间连续性。

这比“用一张照片作为背景，再叠加几个控件”多了实际对象结构；同时，它仍保留照片的稠密观测数据。表示可编辑与表示紧凑是两件不同的事。本版不把前者当作后者的证明。

## 1. 有限像素域上的表示完备性

设原图像素域为 Ω，像素中心为 p，颜色为 I(p)∈{0,…,255}³。为每个 p 建立一个正高斯核，中心在 p，标准差 0.18 像素，并截断到半径 0.49 像素。每个对象的输出颜色为该对象核的加权颜色和除以权重和。

在原分辨率的采样点上，当前像素核的权重为 exp(0)=1，其他像素中心的截断核不贡献，因此该点恢复 I(p)。标签划分将 Ω 分成不重叠对象集合，各对象保留自己的样本，再通过深度与遮挡规则合成原图。

这是对任意有限 RGB8 栅格都成立的构造性表示方法。代价是至少保留这项构造使用的 24|Ω| 比特 RGB 系数，以及标签、推断背景和状态。它不保证高斯个数最少，不保证压缩率，更不降低从自然语言中寻找目标场景程序的困难。

实际代码仍执行高斯指数核、加权累计、归一化、深度测试与颜色量化。独立验收从最终输出读取 RGBA，并另行解码原 PNG 比较。修改一个系数而只改变对应输出像素的测试用于排除源照片直贴捷径。

## 2. 一个对象是一组函数与参数

对象不再只是一个矩形裁剪。它具有以下组成：

| 组成 | 实际字段 / 函数 | 作用 |
|---|---|---|
| 身份与语义 | id、kind、label、sourceId | 让自然语言操作能寻址 |
| 观测域 | labels、RGB 系数、高斯中心 | 保存被看到的颜色与覆盖区域 |
| 表面假设 | depth、depthSlope、normal | 将像素提升到分层空间 |
| 局部变换 | transform | 平移、旋转、缩放、深度修改 |
| 外观函数 | color、exposure、signalState | 保留局部明暗的换色与信号状态 |
| 原型函数 | prototype | 用解析几何采样替换或新增形状 |
| 连接结构 | parent、attached_to | 保持支架、杆、灯的联动 |
| 时间函数 | timeline.tracks | 让参数随时间变化 |

编辑器操作是对这组函数的参数或结构作事务修改。`applyOperations` 生成新状态；不执行模型返回的任意 JavaScript。状态验证拒绝未注册字段、非有限数值、失效对象和父子循环。

18 个对象包含墙面、墙基、道路、道路标线、人行道、斑马线、杆、上臂、灯支架、正面信号灯、侧面灯罩、六个窗户和墙边附件。场景标签来自辅助标注，不是一个已经学会任意照片语义分割的模型。

## 3. 网格关系的两种含义应分开

观测网格提供像素邻接；对象图提供组成和连接。两者共同工作：像素决定可见外观，对象图决定修改的传播范围。

例如杆的变换会传播给上臂、支架、正面灯和侧面灯。墙体移动会携带窗户；墙体换色则只改墙体自身颜色函数，不把窗玻璃一起染色。这里的结构不是所有物理接触都等同于父子变换：`stands_on` 是接触假设，不自动让移动人行道的操作变成杆的父变换。

## 4. 空间投影与时间轨迹

若源像素的整数索引为 (u,v)，其中心为 (u+0.5,v+0.5)，对应表面点：x=u+0.5−W/2，y=H/2−v−0.5，z=d+a(u+0.5−u₀)+b(v+0.5−v₀)，其中 (u₀,v₀) 是以中心坐标表示的枢轴。父子变换后，由正交相机的 yaw、pitch、zoom、pan 投影到输出网格。表面投影 Jacobian J 将圆高斯协方差转成椭圆协方差：C=σ²JJᵀ+εI。

原视角精确模式采用窄核，适合逐点复现。相机变化时，窄核可能产生空洞；交互模式显式加宽核，并可按步长抽样。两个模式是不同质量设置，交互预览不能代替原尺寸精确验收。

时间轴把相机或对象参数写成分段线性、平滑或阶跃函数。视频逐帧调用与编辑器相同的核心。相机变动产生的视差是深度假设的结果，并不等于从单图中发现真实的空间轨迹。

## 5. 光照单独生成，仍接受像素检验

本版将曝光、色温和相对方向光增益作为独立函数，在观测颜色之后、网格合成之前执行。默认参数是严格恒等变换，所以不破坏原视角 RGB 验收。修改光照后，比较的是原观测差异或指定的新目标，而不是继续要求原照片零误差。

观测颜色本来混合了材质、光照、阴影、相机响应。单张照片不能唯一分解这些因素。本版没有真实 BRDF、全局照明或投射阴影求解器。因此改变光照不会自动消除原照片里烘焙的阴影。这一局限在编辑器中标为“相对光照”。

## 6. 隐藏区域与多解

物体移开或换视角后，未曾被拍到的区域需要补全。补全数据带明确的 inference mask 与宿主对象标签，作为该对象额外的高斯样本参加渲染；不是一张固定原图背景。

墙面补全只从可见墙面取样，避免前景边框残影。杆遮住的窗边可以归入窗户的推断面。本版每个网格位置最多记录一层隐藏宿主；同时移动多层遮挡物时仍可能暴露未建模区域。

满足 R(θ)=I 的场景参数通常有多个。像素一致是观测约束；深度、背面、材质和光源还需要多视角、深度传感、交互约束或明确先验。验收报告分别记录观测成功和空间假设，而不将一个分数扩展成所有能力的证明。

## 7. 反馈应修正什么

| 误差类型 | 优先检查的管线 | 允许修改 | 独立复验 |
|---|---|---|---|
| 默认视角 RGB 错误 | 数据、核采样、深度、量化 | 采样/遮挡参数 | 冻结 RGB8 检查器 |
| 换色影响窗或道路 | 语义归属、外观函数 | 标签与操作作用域 | 未编辑对象像素不变 |
| 灯与杆脱离 | 对象关系图 | 附着边与变换组合 | 父子锚点同位移 |
| 视角变化出现洞 | 核宽、采样率、隐藏层 | 显式质量设置与推断层 | 覆盖和推断标记 |
| 光照编辑不合理 | 相对光照/材质模型 | 公开的光照函数 | 默认恒等与目标差异 |
| 浏览器不支持浮点混合 | 执行后端 | 共享 CPU 回退 | 实际 RGBA 输出 |

0.4 实现了可检查的参数与结构编辑、后端能力选择和有界反馈验证；它没有实现一个会自主改写任意算法并保证收敛的多级 RSI 系统。未来扩展应将候选修复、代价、回滚条件和独立验收保留下来，避免为了通过检查而修改检查本身。

## 8. 与现有研究的关系

- [GaussianImage](https://xingtongge.github.io/GaussianImage-page/)研究二维高斯的图像表示。本版借鉴位置、协方差和颜色共同表达像素的方向，但没有复现它的优化和压缩器，也不借用其速度指标。
- [2D Gaussian Splatting](https://surfsplatting.github.io/)的二维高斯是嵌入三维的定向面元，并以多视图约束学习。本版仅有单图假设表面，不能等同该重建结果。
- [3D Gaussian Splatting](https://repo-sam.inria.fr/fungraph/3d-gaussian-splatting/)提供可见性相关的三维高斯场优化和渲染。本版没有运行其多视图训练流程。
- [Gaussian Grouping](https://github.com/lkeab/gaussian-grouping)将分组身份用于对象编辑。本版采用显式对象标签和父子图，不声称完成其分组训练。

因此这版的研究价值在于把观测可验收、语义可寻址、函数可修改、结果可导出连成一个实际系统。进一步的紧凑表示、物品原型学习和多视图空间恢复，应作为独立可测的下一阶段。
