# CRF 图形计算编辑器 0.9：实现、实验与验收

**交付性质：研发候选与可复现实验包。完整照片级目标未通过，不能作为“达到目标”的正式版本。**

本轮在原 0.8 源码提交 `26f9b85a2b25a84ef7afd9ace98a2930e5ab5851` 上开发。原有街景、果物、风景以及历史编辑器继续保留；首页维持 0.8，可从“0.9 研发预览”进入 `studio09.html`。没有把较早的可用案例换掉。

本报告区分三件事：程序能否生成、输出能否准确重绘、画面是否达到照片真实感。前两项已经取得可验证结果，第三项仍未达到用户目标。`acceptance.json` 的 `overallAccepted` 保持 `false`，180 任务终测没有启动。

## 1. 本轮实际实现

| 模块 | 实现与作用 | 能力范围 |
| --- | --- | --- |
| 语义场景 | `crf.generative_scene.v0.9`：稳定对象 ID、类型、尺寸、颜色、材质近似、连接关系、环境、光照、相机、种子 | 明确实现的有限形态函数族；没有证明数学上的通用完备性 |
| 原生求像素 | 解析图像平面形态、覆盖率、近似法线、共同线性光照、可采样高斯场与有限共享系数基 | 混合表示；并非整个画面都由一个纯 RGB 高斯求和网络生成 |
| 参考学习 | DeepSeek 搜索、真实图片输入、描述、像素统计提取、单图高斯拟合、共享模型更新 | 在线主要学习颜色矩与四个高斯频带 RMS；没有在线学习任意新形状 |
| 同一任务闭环 | 规划→需要时学习→生成场景→实际渲染→看图评价→有界修订→持久工程 | 最多三候选、两次质量反馈；失败保留，不无限重试 |
| 街景编辑 | 混合边缘换色、正面信号灯移动/删除、墙缝与纹理语境补齐、撤销 | 隐藏墙面是推断；没有隐蔽真实背景的观测证据 |
| 编辑器 | 对象编辑、灯光与纹理参数、左右视差、时间轴、保存/重载、PNG/视频/工程下载、任务恢复 | 新生成场景支持自然语言修改；原街景的精确操作使用对象面板 |
| 离线执行 | 与编辑器共享求值器的零安装 Node CLI，项目内嵌精确外观模型 | 无 API 调用即可重绘；不读取生成参考照片作为最终画面 |

**本轮没有使用 Blender、三角网格建模或外部成品图片生成器替代 CRF 出图。** 山、树、墙、窗、果物等结构来自已实现的程序函数；自然经验的一部分来自真实提取的统计与高斯系数。结构规律仍以手工实现的函数为主，这是当前逼真度受限的重要原因。

## 2. DeepSeek 实际跑了什么

真实任务使用服务返回的 `deepseek-flash` 模型标识。请求、实际搜索证据、图片输入、tokens、修正及失败均保留在实验记录中。没有据此宣称与某个旗舰图像模型达到同等效果。

### 2.1 三类各十轮参考流程

| 类别 | 完成轮数 | 取得并去重的参考 | 已落盘的预览高斯拟合 | 每类至少 40 个来源的计划条件 |
| --- | ---: | ---: | ---: | --- |
| 建筑 | 10 | 33 | 33 | 未达到 |
| 自然风景 | 10 | 33 | 33 | 未达到 |
| 静物 | 10 | 35 | 35 | 未达到 |
| 合计 | 30 | 101 | 101 | 不以总数抵消分类不足 |

“101 个”按来源页面、可解析照片身份与文件哈希去重，不代表已经人工核查了 101 个完全独立拍摄场景。下载失败与排除项保留在各轮记录中。

搜索路径也分别记录：29 轮观察到模型原生搜索，另 1 轮使用提供方的真实搜索 fallback。该 fallback 轮没有下载到新图片，不能计成一次实际看图。共有 29 个真实图片描述批次，合计 101 张图像输入。没有把“说过搜索”当成搜索已发生。

这批运行的单图拟合采用最长边 192、1,024 个高斯和 8 次几何优化，属于**预览拟合**。浏览器交互学习的默认预算与离线高保真街景不同。101 次拟合成功不等于 101 个高保真对象已经入库。

### 2.2 学到的参数究竟是什么

在线十轮更新的是跨图线性 RGB 一、二阶统计与四个高斯频带幅度。共享模型从原 23 个训练观测增加到 124 个观测。模型版本和像素输出确实受这些数值影响，但这不等于 DeepSeek 权重训练或照片生成器训练。

另有独立 H2 实验：5 个水果训练实例在规范坐标中拟合 289 个高斯基，学习均值与 rank-4 PCA，共 4,339 个共享数值。在线新增的 101 张参考没有重新训练这个基，报告与模型快照明确写出 `generatorBasisRetrained:false`。轮廓学习的有效同类样本不足，运行时没有把它当成已学成的形状生成器。

这四件事分别保存：单图观测拟合、共享统计更新、有限对象系数基学习、语言模型本身的权重。不能把它们混为一个“已学会物体”的计数。

当前反馈能修改参数和场景，管线选择遵循已实现的有限分支；没有实现自主发明新算法并通过留出验收的完整多级 RSI。

模型看到了实际候选图并给出两轮修正。最后选中的结果是满足既定参数选择规则的候选，并没有获得独立人工真实感认证。全量索引见 `web/assets/v09/generated/index.json`；每案原始 PNG、精确场景与记录均可在编辑器中下载。离线包另含三十个候选的场景程序和 JPEG 预览，可重算无损 PNG。

### 2.4 调用量与模型快照

`learning-v1` 与 `showcase-v1` 合计记录 128 次实际请求：127 个带 requestId 的模型请求，加 1 次无 requestId 的真实搜索 endpoint 请求。提供方累计 tokens 为 1,036,539，其中学习 705,623、生成 330,916；初始失败、重规划和结构修复均在内。没有提供账单金额，报告不推算未经核对的实际扣费。连接探针及后续生产服务验收另行记录，不混入这两个实验批次。

03 建筑案例使用较早的 `shared-122a6823` 模型快照，其余九个使用 `shared-1b02095c`。每个场景携带自身的精确模型，独立重绘必须使用该快照，不能拿最终全局模型替换后仍宣称同一张图。

## 3. 原街景：可以量化的改善

固定原始尺寸为 667×1000，没有通过缩图改善分数。按同一规范解码、颜色与 RGB8 取整规则测量：

| 指标 | 0.8 基线 | 0.9 街景候选 |
| --- | ---: | ---: |
| PSNR | 43.4547 dB | 48.3171 dB |
| SSIM | 0.975536 | 0.990796 |
| RGB8 平均绝对误差 | 1.151816 | 0.660701 |
| 最大通道误差 | 33 | 3 |
| RGB 完全相同的像素比例 | 15.8253% | 30.8178% |
| 高斯数 | 65,536 | 165,536 |

本轮增加了 **100,000 个来自已知观测残差的细节高斯**。因此这是增加显式信息量后的保真改善，不能写成同预算算法胜出，更不能写成从语言生成新照片。街景达到了这一张图的 PSNR≥38、SSIM≥0.98 近似重建门槛，仍没有达到 100% RGB 严格相同；固定十二图整组也没有完成。

### 换色、边缘和移除

混合边缘用前景/背景颜色线估计覆盖率，避免整片边缘直接被墙色染透。独立亚像素合成真值测试的边缘 MAE 为约 0.3275、最大误差 2。照片本身的自然 alpha 没有真值，因此不能把合成成绩直接称为自然边缘的真实误差。

已声明的受保护不透明区有 219,140 像素，换色后零变化；二十条编辑状态检查中撤销恢复准确。保护区与混合边缘分别验收，没有用大块未变化区域稀释边缘误差。

删除信号灯后由可见墙面语境计算背景，保持墙缝、明暗和局部纹理。在四个隐藏真值不提供给补全器的受控开发遮挡任务中：

| 场景 | 隐藏 ROI 的 RGB8 MAE | SSIM |
| --- | ---: | ---: |
| 亮墙 | 1.3297 | 0.95677 |
| 暗墙 | 1.3133 | 0.95734 |
| 墙缝 | 1.3215 | 0.96526 |
| 阴影边界 | 1.3740 | 0.95784 |

这些受控测试满足当前局部门槛；真实信号灯后面原本是什么仍不可观察，只能说补齐合理性有所改善。没有声称恢复了被遮挡世界的真值。

## 4. 新图的真实感：仍然失败在哪里

三轮研究假设分别尝试了程序高斯统计场、共享外观与规范系数基、共同照明与结构细化。它们形成了可运行模块，但尚未证明未见场景能达到照片真实感。

在冻结的早期统计模型上，十二个留出样本的高斯频带描述误差由手工基线 0.000305071 变为学习后的 0.000309779，只有 5/12 改善，没有获得整体改善。这个指标只涉及频带描述，不是照片质量评分；P3 因而不能凭此通过。

开发阶段直接看图仍可见：

- **建筑：**窗框过于规则，玻璃与墙面层次不足，路面线条机械，光影与接触的精细变化不够。
- **高山湖与森林：**树群形态重复，近景树与岸的接触、尺度和遮挡存在问题；山体有局部矩形边界，倒影是程序缓冲中的图像近似。
- **海岸：**海岬有裁切底边，波纹重复，泡沫像刷痕；石块较扁，接地不充分。
- **水果与花瓶：**共享明暗和局部细节有进展，但梨的轮廓偏理想化，叶片扁平，果皮斑块与粗糙度分布仍程序化，接触阴影不够自然。

这些是开发审读结论，没有冒充真人盲评。模型自评没有被用来发放照片级合格证。

**根本缺口仍是能生成新结构与材质细节的条件视觉模型，以及跨对象共同成像的约束。** 更密的观测高斯能更好编码已有照片；少量颜色/频率统计能调整纹理分布；两者都不能自动提供任意新场景所需的形状、部件、材质与照明联合规律。继续堆参考张数、提示词或推理次数，不能替代这部分机制。

### 数据重叠与新模型评价

来源身份审核发现，建筑学习中的一张 Pexels 照片与旧 test 集同源，虽然下载字节哈希不同。当前在线统计模型含该来源。原有留出成绩只属于更新前的历史模型，**不适用于新共享模型**；新模型尚没有新的独立留出泛化成绩。

后续终测前需要按拍摄主体/来源组冻结新数据划分，并在检索与入库阶段排除留出来源。当前 101 个在线观测没有完整的独立 train/validation/test 分组，不能声称数据无泄漏。相关命中与模型快照都保留，未删除失败证据后重算“好成绩”。

## 5. 视频与视角的准确含义

固定选择 01 建筑、04 高山湖、08 静物作为媒体案例。每案从同一场景函数逐帧生成 1920×1080、24 FPS、120 帧，共 5 秒；提供正面、左侧、右侧三个 PNG。媒体脚本解码所有源帧和 MP4 帧、校验帧数与相机轨迹，并记录每帧哈希及相邻差分。完整结果在 `reports/v09/media_verification.json`。

相机采用预先固定的平滑轨迹：`u=t/5; s=u*u*(3-2*u)`，水平偏移增加 `0.056*s`，垂直偏移增加 `-0.008*s`，缩放乘 `1+0.065*s`；左/右额外偏移为 ±0.042，并保留场景原有相机参数。没有为了通过检查把运动幅度缩成静止画面。

视频以 1920×1080 为容器，4:3 原场景在中央 1440×1080 视口中求值，左右各 240 像素为不透明黑边，保留物体比例。初次工程检查发现直接按 16:9 求值会把果物横向拉宽，已修正导出编排并重新渲帧；旧诊断记录保留，未将旧拉伸结果作为最终视频。

浏览器导出还修正了编码色彩问题。原 VP8 输出即使补上容器标签，解码帧仍采用不一致的范围/矩阵。0.9 的新导出器优先选择实际支持的 VP9，保存编码器声明，并解析关键帧交叉检查，拒绝不兼容的 VP8 回退。同一实际静物场景重导后，120 帧的流级/帧级色彩信息一致；普通解码首帧内容区相对独立求值结果的 RGB8 MAE 从 10.7742 降到 1.3483、RMSE 从 11.7404 降到 1.7785。比较未强制覆盖解码颜色设置，结果仍属于有损视频。三个离线 MP4 则显式转换并标记 BT.709 YCbCr 范围和 sRGB 传递函数，各自解码首帧内容区 MAE 为约 1.36、1.48、1.41。旧错误诊断与当前结果均保留。

当前空间语义是**有限图像平面深度分层视差与解析推断**。它没有经过真实多视角标定验证，也没有恢复完整三维世界。原街景左右查看更有限，仅是二维图像平面裁切。水面取当前已绘程序缓冲的镜像并施加扰动，能反映远山变化，但不支持任意物理反射光路。

本轮尚未集成 Depth Pro 2 权重。场景中的深度值是声明的分层参数，不能把当前视差效果标为 Depth Pro 2 重建，也不能由单张照片的拟合分数推导未见视角的准确性。

相邻帧差分证明发生了连续计算，不能代替运动补偿后的闪烁、遮挡和空间真实度评估。MP4/WebM 是有损编码，不宣称视频字节等于原始像素。**G4 的真实空间质量门槛仍是部分完成。**

## 6. 如何实际使用

1. 打开 `studio09.html`，左侧选“DeepSeek · 实际生成”的任意案例。点击对象，调整颜色、类型、位置、大小、粗糙度；或调整共同灯光。
2. “DeepSeek”页填写描述。生成已有类别可复用共享函数；需要新参考时启用“先执行十轮参考学习”。未实现的对象类别会明确停止。
3. 生成任务显示阶段，候选经过实际渲染后再供模型看图修正。任务与模型保存在本机 IndexedDB；中断后从已保存任务恢复。关闭页面瞬间未收到响应的调用不能保证没被提供方计费。
4. “保存工程”同时保存到本机并下载完整 JSON。场景内嵌当前精确模型，后续共享模型更新不会悄悄改变旧作品。
5. “导出 PNG”按场景完整画幅重算。“导出视频”对原生场景实际计算 120 帧；完成后保留可再次下载的链接。
6. 案例下方提供本次原始 PNG、场景函数和调用记录；三个媒体案例还有 MP4 与三视图。当前编辑不覆盖原始实验文件。

服务端接口为 `POST /api/crf/native/generate`，模式包括 `plan`、`generate`、`edit`、`critique`。DeepSeek 生成受限声明式场景程序，由同一 CRF 求值器运行；不会执行模型返回的任意脚本。凭据仅在服务端使用，不写入网页或离线包。具体协议见 `docs/v09/PROVIDER_API.md`。

## 7. 交给另一个 LLM 或本地运行

解压 `CRF_0_9_Render_Kit.zip`，使用 Node.js 20 或更新版本。PNG 编码采用 Node 内置功能，无需 `npm install` 或联网调用模型。

```sh
node scripts/render_v09.cjs --all web/assets/v09/generated/index.json outputs
node scripts/render_v09.cjs web/assets/v09/generated/showcase-v1/08_three_fruits.scene.json fruit.png
node scripts/render_v09.cjs --views web/assets/v09/generated/showcase-v1/04_cold_alpine.scene.json views
node scripts/render_v09.cjs scenes/street_blue.json street-blue.png
node scripts/render_v09.cjs scenes/street_signal_removed.json street-removed.png
```

另一个 LLM 可以修改同一场景的对象参数或调用 `CRF09.applyOps`，再执行求值器。新增类别需要实现对应的函数，不能只把名称改成一个未支持对象，就宣称该对象已学会生成。

```sh
node scripts/render_v09.cjs --frames web/assets/v09/generated/showcase-v1/08_three_fruits.scene.json frames --fps 24 --duration 5 --width 1920 --height 1080
```

## 8. 已核验的工程路径与尚缺的验收

浏览器真实打开了原街景和 DeepSeek 静物案例，完成 PNG 下载、工程保存、形态修改、撤销、页面重载以及从本机工程恢复。真实静物导出的 1024×768 PNG 与发布求值器输出逐 RGBA 完全相同，保存重载后的再次导出也一致。同一 DeepSeek 静物案例还实际导出了 5 秒 VP9 WebM：1920×1080、24 FPS、120 帧，按原场景比例求值并留边；全部帧可解码，色彩声明与实际解码帧一致。编辑器中的静物 MP4 下载也与已验收文件逐字节一致。

这些浏览器检查在托管预览执行。批量 DeepSeek 实验通过与编辑器相同的任务状态机和渲染核心执行，不能冒充十个生产登录后的浏览器端到端任务。生产服务接口检查与浏览器身份验收另列；主使用设备上的 p50/p95、1K 编辑 p95≤250ms 仍未完成。

独立保留校验以 722 个旧网页文件为基线：721 个要求不变的文件保持字节一致；首页仅增加 0.9 入口，继续打开 0.8。旧 ZIP 的发布体积通过共享压缩片段减少，原下载 URL、完整文件字节、SHA 与 Range/HEAD 行为仍需通过构建验证，不能以删掉旧案例节省容量。

工程测试覆盖参数合法性、连接父链、隐藏继承、相机连续性、明确空模型语义、导入失败的原子性、历史状态恢复、真实图像反馈、有限修复、取消/恢复、下载字节与归档路由。测试成功不作为画质达标证据。

## 10. 下一步由这轮证据决定的工作

继续推进应先解决 P3：建立可靠的对象分割与规范对应，以冻结的独立开发留出集比较“程序结构＋统计”与“条件模型输出高斯参数”。训练目标必须同时约束轮廓/部件、表面细节、照明与对象接触，验证实际新生成而不是对已知照片拟合得更好。需要较强视觉先验时，应声明具体权重、依赖、训练来源和可编辑输出方式，不能用完整外部成图转高斯代替这一机制。

数据侧先修正来源级留出隔离；评估侧保持独立盲评与既定参数/像素测试。只有未见任务的真实感与语义共同改善后，才进入三类扩展与 180 任务终测。当前三轮研究未满足这个出口，继续无限增加展示图不会改变这一结论。

本轮交付的价值是：共同的可执行接口、实际而非模拟的搜索/看图/函数更新、可追踪失败的任务闭环、可编辑的真实模型场景、逐像素可重复的工程与局部重建改善。用户要的通用高逼真代码生图与视频目标仍需要核心生成机制的突破。
