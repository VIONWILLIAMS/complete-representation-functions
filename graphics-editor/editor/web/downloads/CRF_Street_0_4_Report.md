# CRF Street 0.4 · 交付与验收报告

日期：2026-11-21

## 1. 这次交付的结果

0.4 把同一张街景照片建立为可操作的 CRF 编辑器：18 个语义对象拥有各自的观测高斯、变换、颜色函数、相对光照参数、关系与时间轨迹。页面支持对象选择、换色、信号状态、移动/缩放/旋转、复制/删除/原型替换、视角切换、撤销重做、JSON 操作、图片与视频输出。

前端使用原生 HTML/CSS/JavaScript。CPU 与浏览器回退共用同一个高斯函数核心。没有使用 Blender，没有把原照片作为隐藏背景贴上去通过验收。扫描阶段读取原 PNG 生成观测数组；运行渲染读取明确存储的 RGB/语义/推断数组和函数状态；验收再另行独立解码原 PNG 比较。

## 3. 100% 的准确含义

0.4 改变了 0.3 的表示约束：现在明确允许保存每个像素的颜色系数。每个像素在原网格上由一个标准差 0.18px、有限支持半径 0.49px 的高斯核表示。原采样中心上的核权重为 1，邻核在支持域外，因此经真实核累积与归一化，可以逐值回放。

这证明的是**稠密观测表示的正确回放及其可编辑性**。它不证明照片被压缩，不证明只凭简短程序推导全部细节，也不证明单图的真实三维世界已经恢复。

## 4. 交互与导出如何工作

选择对象后，修改对应函数的参数。改变颜色只影响对象自身的颜色函数；移动父杆则通过父子关系带动上臂、支架、正灯和侧灯。循环父子关系会被拒绝，整批 JSON 操作失败时不提交状态。

非整数位移、缩放、旋转或相机变动默认切换到连续的交互高斯模式，避免原采样专用窄核造成空洞。撤销或重置回原几何后恢复精确模式。用户仍可主动选择质量，但界面会持续提示适用范围。

PNG 导出读取实际渲染缓冲区，不包含 UI 和选择框。场景 JSON 保存函数参数、关系与轨迹，需配套本工程观测数据。完整工程 ZIP 同时包含源图、扫描器、数据、渲染核心、界面、测试、报告与预制输出。

预制视频使用同一个核心，逐帧求值 72 次，含小幅往返相机运动及第 36 帧的绿灯切换。RGB 源帧为 667×1000；H.264 的 yuv420p 编码在右边补 1 列黑像素成为 668×1000，不对源列做缩放。MP4 是有损视频，不用于静态精确 RGB 验收。

浏览器最初的 MediaRecorder 路径已经验证能够下载，但在当前 CPU 环境实际只捕获 6 帧。因此默认导出已改为 WebCodecs 逐帧生成、显式时间戳编码与 WebM 封装。实际从编辑器点击下载后，文件解码得到 72 帧、24 fps、3.000000 秒、667×1000；界面操作、渲染、编码和下载等待合计约 47 秒。慢设备可以多花时间生成，成片仍保留全部时刻。MediaRecorder 只作为能力不支持时明确标示的实时录制回退；不能把成片 24 fps 当作实时运行性能。

## 5. 当前性能与空间边界

本次云浏览器没有 WebGL 2，实际启用 CPU 回退。最终独立浏览器批次中，冷启动精确渲染约 766ms，热精确渲染约 209ms，原尺寸交互 LOD 约 289ms。拖动和播放时 CPU 预览可降到 334×500；像素核验回到 667×1000。上述只是当前环境测量，不是帧率承诺。

WebGL 2 实现已编写，包含真实浮点 Gaussian 累积、归一化、深度和对象 ID 拾取；它在当前环境没有完成 GPU shader 执行与像素验收。工程保留显式 CPU 回退，不用性能推测替代测试。

其他视角是单图假定深度与斜率表面的 2.5D 正交重投影。它们可编辑、可动画化，但不是多视图训练得到的 3DGS，也不是经过观测证实的背面。大幅改视角会出现未建模边缘；移开物体后的补全仍可能有近似边界。只记录一层隐藏宿主，复杂多层移除没有完整建模。

相对曝光、方向光增益和色温是独立函数，默认严格恒等。它们并没有把真实材质和原光照唯一分离；原照片烘焙阴影仍存在。基础原型包含椭圆、矩形、三角、菱形、圆环及信号状态函数，不等于已经具备任意物品的高质量生成能力。

## 6. LLM 如何操作

内置示例语句由本地有限规则解析，没有隐含远程 LLM 请求。其他模型应把语义翻译为以下注册操作，然后经编辑器验证和应用：

```json
[
  {"op":"set","id":"wall.main","path":"color","value":{"tint":[85,135,175],"amount":0.72}},
  {"op":"set","id":"signal.main","path":"signalState","value":"go"},
  {"op":"set","id":"pole.main","path":"transform.x","value":12}
]
```

这让语义作用于可寻址、可撤销的表示结构。完整字段、轨迹和接口见 `docs/ENGINE.md`、`docs/EDITOR.md`、`docs/LLM_OPERATIONS.md`。

## 7. 反馈与下一步

本轮实际修正了隐藏样本重复累计、杆脚深度穿透、侧灯背板和吊架漏标、轨迹关键帧迟滞、录制失败清理，以及窄核在非整数编辑后的空洞问题。修正分别作用于数据、关系、渲染、时间和界面管线，最终仍由独立检查器复验。

这形成了可复验的多层改进流程，但不是一个已经会自主改写任意算法并保证收敛的 RSI 系统。下一阶段应分别验收：更少高斯下的失真/成本；多实例物品原型；多视图深度约束；材质与光照分解；逐对象缓存与 GPU 实测。不能用原视角零误差替代这些目标。

## 8. 核心来源与复现标识

研究依据：

- [GaussianImage](https://xingtongge.github.io/GaussianImage-page/)：二维高斯图像表示；本版未复现其压缩器。
- [2D Gaussian Splatting](https://surfsplatting.github.io/)：三维空间中的定向高斯面元；本版不是其多视图重建。
- [3D Gaussian Splatting](https://repo-sam.inria.fr/fungraph/3d-gaussian-splatting/)：三维高斯场的优化与可见性渲染；本版没有运行该训练流程。
- [Gaussian Grouping](https://github.com/lkeab/gaussian-grouping)：分组身份和对象编辑；本版使用辅助标签与显式关系图。
