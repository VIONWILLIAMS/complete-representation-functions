# CRF 图形计算编辑器 0.5：交付与技术验收报告

日期：2026-11-21。在线编辑器：https://crf-street-04-lab-4d86.laterafter950.chatgpt.site/

## 1. 本次交付解决了什么

0.5 把上一版暴露的两个具体问题落实到表示层：换墙色时，物体轮廓中的混合像素会随背景一起更新；隐藏正面行人信号灯时，原位置显示带纹理和连续墙缝的推断墙面，选择框同步消失。界面统一命名为 **CRF 图形计算编辑器**，增加四个可编辑案例、多角度图库、五秒时间轴与逐帧视频导出。

本版有两种明确区分的表示来源。街景、实拍水果和湖畔案例来自冻结照片的稠密 RGB 观测；苹果与梨子的摄影棚案例来自参数曲面和程序材质。它们共享对象状态、操作协议、高斯采样、相机、时间轴与导出接口。用代码表示和修改已知画面，以及从已注册物品函数生成新画面，已经可以在同一个编辑器中实际操作。

三张照片在各自冻结的参考尺寸下，共 **1,571,800 个像素**完成严格 RGB8 一致验收，MAE 与最大通道误差均为 0。程序水果另有 480,000 像素的生成基准复现检查，不计入实拍照片总数。这个结果证明当前表示的原视角复现能力；稠密 RGB 系数仍被保存，不能把它解释为从一句话压缩恢复照片或已恢复完整真实三维。

## 3. 完备表示函数在本版中的工程定义

这里把 CRF 实现为可执行场景程序：

\[
I_{c,t}=R\bigl(\{F_i(\theta_i,t)\},\,G,\,C_c(t),\,L(t),\,B\bigr).
\]

`F_i` 是一个对象的观测场或程序生成器；`θ_i` 包含颜色、变换、形态和其他参数；`G` 保存附着关系；`C` 是相机；`L` 是相对光照；`B` 是带来源标记的背景补齐策略。`R` 对高斯样本求值、投影、累积和合成，输出实际像素。前端控件和 LLM 都通过同一组已注册操作改变这些参数。

“完备”在这里是研究目标与表示约定。它没有被证明为一种能有效生成一切视觉世界的最优语言。0.5 的重要进展，是把对象、边界、补齐、几何与时间的可编辑关系写成可以执行、检查和回退的程序，而不是把“可表示”直接当成“能够从任意自然语言可靠求解”。

### 3.1 像素与高斯的关系

照片案例为每个源像素保留 RGB 系数和对象归属。原视角精确模式使用位于像素中心的窄高斯核，并执行真正的核求值、归一化、深度和图层合成；独立参考 PNG 只用于比较。该模式不依靠把参考图片直接绘制到最终画布来通过检查。

原尺寸精确模式的参考标准差为 0.18 像素，截断支持半径为 0.49 像素。它适合原坐标复现，但不适合连续亚像素变换。改变几何或相机后，编辑器自动采用较宽的交互核，避免窄核重投影留下采样空洞。改变相机、颜色、光照后，输出与原图不同属于目标编辑的正常结果。

照片的空间表示主要是带深度与斜率的语义表面，即 2.5D 假设。水果生成器具有真实三维参数位置和逐点深度，但也采用简化可见性与光照模型。本版没有训练官方 3D Gaussian Splatting 的多视角场景模型。[3]

## 4. 换色边缘：保留原始像素，修正背景贡献

0.4 的问题不仅是轮廓位置。物体边缘常混合前景和墙面颜色；把混合像素整体划给物体后，墙面换成蓝色，边缘仍保留旧墙色，因此出现浅色边圈。继续扩大硬掩码会把更多背景固定到物体上，不能从根本上解决这个现象。

0.5 增加 `boundaryMixture`，为声明的边界像素保存宿主背景、估计背景颜色 `B` 和背景贡献比例 `β`。它保留原始 RGB 观测 `I`，通过背景变化的差值更新边缘，而不是先把原始图像重建成一个有误差的前景图层。主引擎 `applyBoundaryMaterials` 的实际更新式为：

\[
I'=\operatorname{clip}\left[S_o(I)+\beta\left(S_h(B)-S_o(B)\right)\right].
\]

`S_o` 是该边缘所属对象的当前颜色与光照变换，`S_h` 是宿主墙面的变换。当两者都未改变时，差值为零，原始 RGB 锚点得到保留。墙面换色而前景不变时，只修正估计的背景贡献。该表达与图像 matting 的混合像素观点有关，但本实现是有来源标记的局部估计，并没有宣称完整复现 Levin 等人的闭式 matting 算法。[1]

街景声明了 **10,319** 个边界混合记录。指定换墙色测试中，**10,318** 个声明边界像素实际发生变化；声明区域以外的非墙面像素变化数为 **0**。剩余一条记录经量化没有产生 RGB8 差别。这个检查确认修改遵循边界归属契约，并不意味着估计的混合比例在物理上全部准确。

## 5. 隐藏信号灯：像素语境补齐

补齐管线不再只传播低频颜色。Street 墙面使用同一表面的可见区域作为供体，分别处理：

1. **低频照明**：延续邻近墙面的明暗趋势，保留原有大尺度阴影语境。
2. **高频纹理**：转移可见同墙面的细节残差，按局部亮度调整幅度，避免得到平滑色块。
3. **结构接缝**：从可见列拟合墙缝位置并延续横向相位，避免接缝在原灯体位置中断。
4. **来源与遮挡**：补齐样本记录 `inferred`，前景像素不作为墙面供体；对象隐藏后由宿主墙面图层显露这些样本。

这一处理借鉴“纹理与结构同时延续”的修复目标；它是本场景可重跑的专门实现，不是对 Criminisi 等人完整优先填充算法的复刻。[2]

隐藏 `signal.main` 后，灯体目标区域的 **4,288** 个像素均变为带推断标记的墙面，目标区域以外改变数为 0，实际画布没有透明洞。浏览器还验证了隐藏前可见、隐藏后不可见的选择框状态。

| 同一局部检查 | 0.4 | 0.5 | 指标解释 |
| --- | ---: | ---: | --- |
| 补齐纹理标准差（RGB 级） | 0.151 | 4.162 | 检查是否退化成平滑色块 |
| 连续墙缝的最小对比度（RGB 级） | 0 | 39.703 | 检查接缝是否在补齐区断裂 |
| 接缝极小值所在行范围 | 445–450 | 447–448 | 检查拟合结构的连续位置 |

这些是结构质量检查，不是隐藏区域的真实性评分。照片没有提供灯后墙面的真实像素，因而无法证明补齐就是拍摄现场的唯一真实背景。完整数值见 `reports/v05/boundary_context.json`。

## 6. 原生生成物品：苹果与梨子

`crf-fruit.js` 从参数曲面产生果体、果梗和叶片。果体位置与法线来自三维函数，表皮颜色、微小斑点与高光由确定性材质函数产生。种子控制纹理，形态参数控制鼓度和颈部，粗糙度控制高光。改相机后会重新求值可见面、投影及深度，而不是平移一张水果贴图。

摄影棚背景也是程序函数。接触阴影随着物品变换重新生成，并使用乘法透射合成；多个阴影可自然重叠，不会用一块亮背景覆盖另一块阴影。阴影不占用水果对象 ID，点击地面仍选择背景。这个阴影假设仅用于摄影棚案例，不会自动应用到普通照片。

浏览器实际操作显示，苹果替换为梨子改变 **83,320** 个像素；形态修改改变 **42,533** 个像素，撤销后逐像素恢复原状态。这些证据说明对象参数确实到达渲染结果。它们不证明程序水果已经达到与某张实拍水果照片一致的光学外观。完整函数与参数见 `docs/FRUIT_GENERATOR.md`。

## 7. 多视角与五秒视频

每个案例提供原视角、左侧、右侧和抬高观察四幅图像。照片案例的其他角度由深度假设和补齐层推演；生成水果的视角则来自其参数几何。展示图调用同一引擎求值，不是与编辑状态无关的另一个图像生成服务。

五秒轨迹包含左右运镜、轻微俯仰与缩放。视频采样时间为 `t=i/24`，`i=0…119`。120 帧各占 1/24 秒，总时长为 5 秒；最后一帧采样时刻是 119/24 秒，不需要重复添加第 121 帧。

| 文件 | 实际解码尺寸 | 帧率 / 帧数 / 时长 | 来源 |
| --- | --- | --- | --- |
| `crf_0_5_street_5s.mp4` | 668 × 1000 | 24 fps / 120 帧 / 5.000 秒 | 同一 CPU 引擎逐帧输出，再编码 H.264 |
| `crf_0_5_fruit_lab_5s.mp4` | 800 × 600 | 24 fps / 120 帧 / 5.000 秒 | 程序水果逐帧输出，再编码 H.264 |
| `crf_0_5_editor_5s.webm` | 667 × 1000 | 24 fps / 120 帧 / 5.000 秒 | 实际点击编辑器导出按钮得到的文件 |

Street MP4 为满足 YUV 4:2:0 偶数宽度要求，在最右补一列，667 个源图列没有缩放。WebM 保留 667 宽度。实际浏览器导出的 WebM 为 **4,863,010 字节**。三个文件都完成真实解码检查，且各有 120 个不同的解码帧。视频采用有损编码，因此不参加静态 RGB8 的逐通道完全相等判断。证据见 `reports/v05/video_verification.json`。

浏览器优先使用 WebCodecs 按时间戳逐帧编码并封装 WebM；编码配置使用 quality 延迟模式，并核对编码帧数。能力不足时会明确显示可能掉帧的实时录制回退。本次验收得到的是完整逐帧导出结果。

## 8. 验收规则与结果

像素严格一致率为：

\[
E=\frac{1}{WH}\sum_{x,y}\mathbf 1\left[\forall c\in\{R,G,B\},\ I_{xyc}=\widehat I_{xyc}\right],\quad
\mathrm{MAE}=\frac{1}{3WH}\sum_{x,y,c}|I_{xyc}-\widehat I_{xyc}|.
\]

100% 通过需要尺寸一致、所有 RGB 通道一致。比较器不会把近似相似度四舍五入成 100%。当前编辑差异和初始原图验收分开显示；换色后的图像不应该被要求与未换色照片相同。

| 检查组 | 结果 | 主要证据 |
| --- | --- | --- |
| 核心、边界、程序物品测试 | 24 / 24 | `tests/test_core.cjs`、`test_boundary_v05.cjs`、`test_fruit.cjs` |
| 共享引擎独立检查 | 13 / 13 | `reports/verification.json` |
| 0.5 案例、编辑与轨迹检查 | 15 / 15 | `reports/v05/acceptance.json` |
| 实际浏览器画布与操作 | 10 / 10 | `reports/v05/browser_verification.json` |
| 三张照片原视角 | 1,571,800 / 1,571,800 像素 | MAE 0，最大通道误差 0 |
| 生成水果重复求值 | 480,000 / 480,000 像素 | 生成基准复现，非照片真值 |
| 三个视频实际解码 | 全部通过 | 各 120 帧、24 fps、5 秒 |

Street 继续使用从早期版本冻结的 RGB8 检查器，见 `verification/pixel_acceptance.py` 与 `reports/v05/pixel_gate/`。浏览器验收独立解码参考 PNG，读取实际画布缓冲区；它不是检查界面上的文本是否写了“100%”。

本次浏览器环境报告 **WebGL 2 is unavailable**，实际执行共享 CPU 高斯路径。GPU 路径存在，但没有把这些 CPU 检查或计时写成 GPU 验证结果。照片边界与程序深度等需要专门支持的帧也可明确回退 CPU。

## 9. LLM 接入与交付组织

LLM 应先读取案例和对象，再生成已注册 JSON 操作。操作事务先校验 ID、范围、关系和时间轨迹；任何非法项会拒绝整个事务。执行后重新读取画布并检查目标区域、边界、非目标区域及结构关系，失败时撤销或提交修正操作。可执行示例见 `docs/LLM_0_5.md`。

内置中文命令是有限本地解析规则，没有在用户不知情时调用远端语言模型。外部 LLM 可以生成这些操作，但“理解任意语义并创建任意新物体”的通用模型不包含在本版中。新物品类别需要注册新的生成函数或提供观测与语义适配器。

交付分为三种使用方式：

- **在线编辑器**：四案例切换、编辑、独立验收、图库与视频可从同一界面使用。
- **单文件离线 HTML**：四案例数值数据、独立参考 PNG、代码和样式嵌入文件；使用支持 `DecompressionStream` 的浏览器即可离线编辑与导出。预制图库、视频播放和下载清单仍指向在线地址。
- **源码包与媒体包**：`CRF_Graphics_0_5_Source.zip` 保存代码、输入图、观测、文档和验收；`CRF_Graphics_0_5_Showcase.zip` 保存多角度图片与视频。二者具有相同的 `CRF_Graphics_0_5` 顶层目录，解压到同一位置合并，即获得完整本地图库。

文件大小与 SHA-256 由 `dist/downloads/manifest.json` 给出。重新打包时生成清单并执行 ZIP CRC 检查，避免只提供文件名而没有真实文件。

## 10. 后续研究应怎样推进

本版提供了多层修正的可操作入口：参数层改颜色与形态，结构层改对象和父子关系，表示层改边界或背景字段，管线层修改扫描和渲染代码并重跑冻结验收。它尚不是自动设计管线、自我改写并保证收敛的多级 RSI 系统。

下一步可以围绕三个可证伪目标推进。首先取得独立的轮廓或 alpha 真值，用专门的边界数据集衡量混合比例，而不只检查编辑隔离。其次收集同一地点的多张有相机信息照片，给新视角保留测试集，检验深度与补齐是否在未参与拟合的角度成立。最后定义新的物品函数族及其形态、材质和几何约束，使用固定输入、冻结检查器和回归预算评估新增能力。

光照分解也需要额外观测：照片中的阴影、反射和曝光目前属于已观测辐射，不能靠一个色温滑块就证明恢复了反照率、材质和真实照明。当前的成果是一个可执行、可编辑、可核验的前端表示系统；单图完整世界恢复、最优表示搜索及通用语义生成仍是需要进一步数据和算法解决的研究问题。
