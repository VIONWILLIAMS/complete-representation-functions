# CRF 图形计算编辑器：开发上下文

## 工作目录与阅读顺序

- `editor/`：恢复的应用源码和资源。开发、依赖安装、构建与项目测试在此目录进行。
- `README_START_HERE.md`：本地启动、包结构和恢复验证说明。
- `plans/CRF_1_1_Implementation_Plan.md` 与 `plans/CRF_1_1_Execution_Plan.json`：完整的 1.1 方案、T00–T26 任务及验收契约；开始开发前完整阅读。
- `CODEX_HANDOFF_PROMPT.md`：开发任务提示词。
- `provenance/`：源码提交、恢复清单与来源记录；`verification/`：本次交接验证。
- `history/`：历史资料，供追溯，不代替最新计划。

## 基线与事实边界

产品基线为 **CRF 1.0**，源码历史标识为 `0.10.0 / v10`，恢复提交为 `0b2fa1c044d073bd8349ef941cc1b213cbe1cfe1`。下一产品版本为 **1.1**。保留旧 schema、报告与原始计划，新增明确的版本映射及开发记录。

本包的文件恢复、构建和测试结果只说明相应基线检查的结果；不证明 1.1 已完成。完整聊天逐字稿未恢复。当前 verifier 是规则、像素与模型评价组合，当前参数修复循环不等于程序级 RSI。

## 必须保持的工程约束

1. 保留 17 个现有入口、旧 URL、原资源及历史工程可访问性与重放能力。
2. 采用二维高斯颜色场、覆盖函数、关系图与成像算子。不转向 Blender、手工网格或模型训练。允许计划范围内的逐观察数值拟合与明确披露的冻结模型推理。
3. 最终像素由声明的程序求值；不得隐藏原始 RGB 贴回、残差图或完整外部成图。分别标记观察、估计、合成与未知内容。
4. 区分形式证明、有限实例检查、数值测量、模型意见与人工评价。证明工具不可用、超时或证据陈旧时保留真实状态。声明 Lean 定理的语义范围与可信基础，拒绝 `sorry` 及未允许公理。
5. L0 为参数修改，L1 为管线调整，L2 必须改变受限程序的算法结构。人工内核升级不能记作系统自主发现。模型补丁须经类型、作用域、预算和有界执行检查。
6. 候选不能改动其自身验收合约、参考内核、验证器、晋升规则或预算账本。M3 仅用开发/选择集试用；M5 冻结后进行正式封存、晋升与新任务实际继承。
7. 硬约束、未知调用、失败与费用记录持久保存；恢复与子任务共用剩余预算。未接通的服务不得用演示状态冒充执行。

## 执行与验收

按 M0–M5 及任务依赖持续推进已授权开发；独立模块可并行，但需在真实编辑器流程汇合。先复现启动、构建、测试和基线，再修改实现；每个阶段保存命令、环境、结果、失败和可重放证据。若有现成 Git 仓库，使用明确开发分支并保持无关改动；ZIP 本身未携带 `.git` 时不要假装已有原仓库历史。

外部发布、远端写入与付费调用遵循当前会话实际授权；计划中的建议预算不是付费授权。缺少凭证或外部条件时，记录具体阻塞并继续可独立完成的工作，不虚构结果，不增加无必要的逐阶段确认。

1.1 正式完成必须同时具备：**计算内核改善、证明层有效、真实程序 RSI 收益、编辑器可运行**。逐项报告通过、失败、未测；任一必要条件未满足，保持候选版。照片质量和实时加速声明按计划分别验收。
