# CRF 1.1 · 可学习对象函数实验分支

> **第二轮视觉质量已交付：** 当前版本 `1.1.0-experimental.2` 的新入口是 `/quality12.html`，启动命令 `npm run dev:quality`。请先阅读 [真实场景质量说明](README_QUALITY.md) 和实际原图对照。下文保留第一轮对象函数工作流，不代表第二轮画质示例。

本分支把 **GUI Service、Agent Harness、Compute Kernel 和本地对象函数学习** 接到同一份工程中：参考图片经过真实小模型训练，得到带固定版本和来源的函数；人和语言模型共同编辑 Scene IR；计算内核据此产生图片与二维运动视频。

当前产品标识为 `1.1.0-experimental.1`。历史 `0.10.0 / v10` 对应产品 **1.0**，原页面、案例、资产和证据保持可访问。完整架构、范围变更和后续研究要求见 [技术升级设计](plans/CRF_1_1_Learnable_Functions_Design.md)；本分支没有把原 1.1 计划中的形式证明、WebGPU 和程序级 RSI 标为完成。

## 1. 本地启动

使用 **Node.js 22 或以上**。从仓库根目录运行：

```bash
cd graphics-editor/editor
npm ci
npm run dev:v11
```

打开：

<http://127.0.0.1:4173/studio11.html>

`dev:v11` 会调用新的本机启动器，并尝试打开浏览器。保持终端运行，按 Control+C 停止服务。端口被占用时可以执行：

```bash
node ../tools/start11.mjs --port 4174
```

也可以在 `graphics-editor/` 目录运行：

```bash
node tools/start11.mjs --no-open
```

首次使用请先在 `graphics-editor/editor/` 完成 `npm ci`。随后 macOS 可运行 `graphics-editor/Start_CRF_1_1.command`；Windows 可运行对应的 `.cmd` 启动器。启动器检查 Node.js 和端口；具体系统、浏览器与目标设备的验证状态应以本分支验收报告为准。

请通过本机 HTTP 地址使用工作台。浏览器 Worker、WebCrypto 和工程加载需要这一运行方式，直接打开 `web/studio11.html` 文件不等价于启动应用。

## 2. 第一条完整流程：学习湖水外观

这条流程不要求模型 API 密钥，也不要求安装 Python 或大型训练框架。

1. 打开新工作台。初始山湖由人工编写的 `sky / mountain / water / cloud` 显式函数计算，可先修改对象位置、大小、颜色或运动速度。
2. 点击左侧 **湖水样本**。工作台读取仓库内已有的 Lautersee 真实照片，默认选取水面区域 `[0.05, 0.70, 0.95, 0.98]`。来源记录指向 Wikimedia Commons，作者与许可证沿用仓库中的已记录元数据。
3. 在参考预览下调整左、上、右、下边界。数值使用 0–1 归一化坐标。覆盖可以保留原 alpha，也可以明确选择人工椭圆；矩形裁剪不会自动变成准确的对象分割。
4. 在 **学习** 面板输入函数名称，使用默认 600 步、隐层宽度 24 开始本地训练。进度、实际 loss、空间留出 loss 和训练结束状态来自真实优化器。取消会停止训练，不把部分结果自动登记为完成模型。
5. 完成后，新的神经外观函数出现在左侧函数库。查看参数数、实例数、版本及来源；点击 **添加到场景** 才会将它用于画面，已有对象不会被训练结果自动替换。
6. 在对象面板修改位置、尺寸、不透明度、色彩乘子、层次和二维运动。每次修改都通过统一 Patch 接口重新计算。
7. 展开 **场景程序**，查看或编辑 JSON Scene IR。点击 **检查并执行** 后，仍由同一内核产生像素；错误引用、非法数值或陈旧草稿不会覆盖当前场景。
8. 点击 **比较直接 / 缓存** 查看实际数值误差与耗时。对照使用明确的小尺寸画幅，不能把这一测量当作任意场景的实时性能结论。
9. 使用 **采用 / 需要改进** 和备注记录人工反馈。记录绑定当前场景摘要、函数版本、实际帧和时间；它是一次具体的人机反馈，不是独立多人盲评。
10. 保存工程、导出 PNG，或导出五秒 WebM。重新导入完整工程可在没有原参考图片的条件下重放已保存函数。

如果参考没有透明度，学习的是所选矩形区域的外观。参考中的照明、反射、背景和遮挡会进入重建结果；这条流程没有自动获得真实材质分解或未知对象生成能力。

## 3. 导入自己的图片与网络参考

**导入图片** 支持 PNG、JPEG 和 WebP，单次训练最多 8 张参考。工作台记录实际文件摘要、来源组、原始尺寸、裁剪和覆盖；解码参考最长边限制为 1024 px，训练样本最长边为 128 px。训练报告中的解码像素摘要绑定实际进入优化器的数据，原文件摘要和训练像素摘要分别记录。

同一张原图的裁剪与缩放应该属于同一个来源组。空间留出只是当前实例中的像素划分，不能充当独立来源测试。

左侧搜索框支持关键词和公开的 Wikimedia Commons 文件页。点击 **找图** 才会请求参考服务；结果分别记录来源尝试、实际下载和来源元数据。该路径使用公开参考接口，不调用付费语言模型。网络失败、无可用图片或来源受限时保留真实结果，本地导入仍可使用。

多个参考可以共享一个小解码器，通过固定实例编号选择已学外观。对象面板中的 **学习实例** 选择的是已训练实例，不是任意新对象采样。对比两张不同长宽比参考时，应相应调整对象尺寸。

原始参考像素只参与预览、裁剪和训练。完整工程保存模型权重、覆盖、来源与训练记录，不内嵌原始 RGB 图像来代替函数执行。重新训练时需要重新提供原参考；重放已经训练的函数不需要它。

## 4. 计算内核与两种执行配置

| 配置 | 运行方式 | 适用说明 |
|---|---|---|
| **直接函数求值** | 在实际采样位置执行显式、高斯或神经函数。 | 用于数值对照和可承受预算的直接输出。 |
| **缓存预览 · 64** | 从函数本身求出 64×64 的规范外观网格，再进行双线性采样。 | 减少重复小网络调用；它是有误差的数值近似。 |

缓存由已保存的程序和权重生成。证据中分别记录 `generatedFieldCache` 和 `sourceRGBBlit:false`，不把两者混淆。修改函数版本、实例或缓存配置会使对应缓存失效。

颜色在线性 sRGB 中与覆盖度在相同子像素位置求值，预乘合成后再编码为显示 RGB。界面可选择 1×1 或 2×2 采样。源 alpha、人工形状和学习外观的依赖均单独声明。

训练和直接渲染具有计算预算：例如过多步骤与过宽网络的组合、过大的直接渲染画幅或采样数可能被拒绝。界面显示实际错误，减小对应配置后可以重试。参数数少并不自动意味着逐像素网络计算便宜。

当前实现使用 **CPU JavaScript + Worker**。没有启用 WebGPU，也没有把本次 Linux 运行环境的结果外推为 Mac mini M4 的速度保证。

## 5. Agent Harness 与真实模型调用

手工参数编辑、场景 JSON、本地训练、参考读取和导出均可在没有模型密钥时使用。新自然语言编排任务需要服务进程中的 `DEEPSEEK_API_KEY`。

服务没有自动读取 `.env` 的逻辑。请在自己的终端设置环境变量后启动服务，不要把密钥加入场景、浏览器文件或 Git 提交。使用启动器时，环境变量由父终端继承。

**Agent** 面板支持：

- 修改当前场景。
- 重新编排函数。
- 把编辑范围限定为当前选中对象。

模型得到的是轻量函数目录、当前 Scene IR 和任务目标。目录包含用途、固定版本、尺寸、实例信息和允许控制，不包含大数组权重。模型输出经过结构、引用、作用域及预算检查后才进入内核渲染；模型返回的“通过”或自评分不能代替检查结果。

界面的未配置状态来自真实服务配置。适配器实现、供应商真实调用成功、视觉目标达标是三项不同证据。当前环境没有实际供应商调用记录时，报告不会将其写成已验证。

请求期间若用户改变工程，旧候选不会覆盖新状态。失败、取消、用量未知和候选运行记录会保留；GUI 手工修改不会制造 LLM 调用记录。

### 新增接口

| 接口 | 功能 |

## 6. 保存、撤销、反馈与版本

函数由内容 SHA-256 固定版本，场景引用精确版本，不使用模糊的“latest”。修改权重、覆盖或其他封存内容后，旧摘要校验会失败。

**保存工程** 同时尝试写入此浏览器的 IndexedDB 并下载完整 JSON。工程包括 Scene IR、固定函数、实际权重、覆盖、来源元数据、训练记录和人工反馈。本机保存失败会在状态栏显示；下载工程是可转移的交付文件。

撤销与重做恢复场景快照，同时保留当前工程已产生的学习、失败和反馈记录及固定函数版本。界面只保留有限数量的可撤销快照；真实任务记录不会为了显示最新几项而静默截断。达到工程记录上限时，需要导出并开始新工程。

本地训练运行在浏览器 Worker 中。关闭或刷新页面会停止该计算；重开后，未完成的本地训练记录标为中断。保存记录不等于一个在后台持续运行的训练服务。

## 7. 图片与视频导出

**PNG** 使用当前工程的固定函数、当前时间和选定的求值配置生成。图像可直接重新打开；完整工程另外保存可编辑性。

**WebM** 使用现有 `CRFVideo09` 编码器，通过 WebCodecs 逐帧求值和编码：5 秒、24 fps、120 帧，时间固定为 `k / 24`。编码与屏幕预览速度无关；输出保留实际编码器、色彩元数据和时间记录。导出期间可取消。

浏览器必须实际支持所选 VP8/VP9 编码配置。不可用或编码失败时，界面保留真实阻塞，不把一个时间滑块、帧目录或失败文件称为完成视频。

本版视频是固定外观随显式二维轨迹移动，运动参数单位为 px/s 与 °/s。它没有学习自然水流、云层动力学或真实三维新视角。不同平台的压缩字节可能不同；项目和帧程序的可重放性与编码器字节恒等是两个问题。

## 8. 开发、训练与验证命令

以下命令在 `graphics-editor/editor/` 运行：

```bash
# 新增内核、真实训练、Harness、供应商边界与编辑器状态测试
npm run test:v11

# 历史基线回归
npm test
npm run test:v10

# 从仓库已有的真实湖水参考训练并保存权重与报告
npm run train:v11

# 陶器单实例、陶器与橙子共享模型
node scripts/train_example11.cjs
node scripts/train_example11.cjs --conditional

# 固定参数下的直接/缓存对照、重放和多 seed 训练记录
npm run benchmark:v11

# 构建新应用，验证历史公开资源仍可按原字节读取
npm run build
```

`train_example11.cjs` 明确记录命令行预处理：96 px 最长边、固定像素中心最近邻采样。GUI 采用浏览器 Canvas 重采样和 128 px 上限；两者都是同一训练器的实际输入流程，但输入像素不同，不应期待相同训练损失或权重。

构建会生成 `editor/dist/`，新报告进入 `editor/reports/v11/`。历史 `reports/v10/` 不是新版本的验收结果。

### 浏览器集成脚本

```bash
npm run verify:browser:v11
```

脚本需要可用的 Playwright、Chromium、ffmpeg 和 ffprobe；可通过 `CRF_CHROMIUM_PATH` 指定 Chromium 可执行文件。当前核心项目依赖没有把这些浏览器验证工具装进应用运行包，请在验证环境单独准备它们。

脚本在同一进程树中启动开发服务和浏览器，覆盖真实水面训练、取消、入库、添加对象、参数/代码编辑、反馈、工程/PNG 导出、重开、WebM 编码和实际解码。它不调用付费模型 API。

若执行环境禁止浏览器所需的进程或 socket，脚本应保留启动失败记录。使用受支持的实际浏览器完成交互验证时，另保存该次真实操作与制品证据；不能把被阻止的自动化脚本改写成通过。以 [验收目录](editor/reports/v11/) 中的具体运行记录确认当前结果。

## 10. 这次升级的能力边界

已经落地的技术路径是：**参考 → 真实小模型训练 → 固定对象函数 → LLM/人工 Scene IR → CPU 内核 → 图片/二维视频 → 具体反馈和工程重放**。

单图/有限实例重建不等于类别级生成。实例 one-hot、色彩乘子与位置参数不等于学习出了“材质”“湿度”或自然动态等语义控制。参数修改属于 L0，训练权重属于模型学习，人工编写这次内核不计作系统自主 RSI。

原计划中的 Lean/Z3 证明、完整 Pipeline/Operator 搜索、正式封存晋升、WebGPU、未见来源泛化和独立照片质量评审仍需要后续独立实施与验收。这个实验分支提供了共同表示、真实计算与可测量的学习链路，为这些工作提供可运行基础。
