# CRF 1.1 第二轮：真实参考重建与计算工作台

状态：交付设计与验收契约；产品版本 `1.1.0-experimental.2`。`quality12` 只是新增模块的内部文件编号，不表示完整 CRF 1.2，也不表示原 1.1 M0–M5 全部完成。

## 1. 修正本轮交付目标

上一轮完成了可训练对象函数、缓存、工程重放和导出，但实际示例只有一个 128×26 水面训练样本，其他景物是手写形状。缓存与直接求值接近，不能证明它们接近真实照片。本轮以**真实参考在现有原生尺寸下的重建质量**作为首要验收，工程和性能验收分别报告。

用户已批准继续开发并提交 GitHub。沿用 `feat/crf-1.1-learnable-object-functions` 分支和 PR #1；保留上一轮提交用于对照。设计与契约独立提交，随后提交实现和真实验证证据。

本轮先完成一个完整、光照和反射来自同一观察的真实场景，避免把互不相关的局部外观硬拼成风景。该资产属于逐参考拟合的函数表示，不是从一张照片学到通用山、水、建筑生成能力。通用对象建模和真实 LLM 创作闭环仍需独立数据、关系建模与测试。

## 2. 冻结观察与质量契约

机器契约：`editor/contracts/quality12.json`。参考使用已在仓库冻结的 `landscape.alpine.png`，800×531，SHA-256 `b689d5ebe330549b6aa6489c3addffef029e7b803aeb63d61666843642a75222`。这是此前由网络原图规范化得到的 800 像素宽参考；本轮“原生”指这份参考，不把它称为 9528×6328 相机原图。

全图必须同时达到：PSNR ≥32 dB、SSIM ≥0.95、MAE ≤4/255。山林、水面、岸边建筑三处固定 ROI 分别必须 SSIM ≥0.90、MAE ≤6/255。ROI 和指标实现已在实验任务发出时确定；不会依据候选结果选择更容易的区域。

指标使用 sRGB RGB8，固定 `floor(x+0.5)` 量化。SSIM 为每通道 Gaussian 窗口，σ=1.5、truncate=3.5、reflect 边界、population 方差，C1=6.5025、C2=58.5225；ROI 对完整 SSIM map 截取求均值。输出不能为了分数缩小、模糊或改变参考。计算一致性与质量分别形成报告。

PSNR、SSIM 只提供本观察的数值证据；必须同时检查全图和局部边缘、树林纹理、建筑轮廓、水纹。指标通过不等于任意场景、任意倍率均达到照片级效果。

## 3. 表示与优化

对每个源图连续坐标 `u,v`，颜色场为：

`C(u,v) = base + Σ a_i exp(-0.5 q_i(u,v))`，仅累计 `q_i ≤16`。

每个基函数声明 `cx,cy,sx,sy,theta,R,G,B` 八个标量。旋转椭圆定义 `q_i`；RGB 权重允许正负。源图像素中心为 `x+0.5,y+0.5`，最终从浮点场量化到 RGB8。最小 σ=0.35 源像素；最高 262144 个基础核。禁止 delta 像素表、原 RGB/base64、RGB 残差贴图或渲染期重新读取照片。

优化流程：全分辨率观察 → 多尺度初始覆盖 → 稀疏颜色求解 → 根据实际残差增加局部基函数 → 联合优化中心、尺度、方向与颜色 → 导出参数 → 从导出参数重新计算指标。保留未通过的基线与最佳检查点；最终选择不能更改质量契约。

这是显式径向基函数网络的逐观察参数拟合，与上一轮 tiny MLP 共享“坐标到颜色”的目标，但不假设只有增加 MLP 训练步数就能恢复细节。参数容量、原 RGB 字节数、JSON/压缩字节数全部披露；不把较大参数资产包装成高压缩率证明。

## 4. 三层职责

| 层 | 本轮具体职责 | 可验证输出 |
|---|---|---|
| GUI Service | 原图对照、同位置细节查看、参数修改、保存、导出、错误显示 | 实际浏览器交互和下载文件 |
| Agent Harness | 消费有版本和摘要的函数资产，限定视口/图像调整操作，区分冻结质量与当前编辑状态 | 同一项目 API 可供 GUI 和程序调用；现有 agent 工作台继续可用 |
| Compute Kernel | 有界二维高斯函数求值，直接采样目标像素，支持 native/2×/ROI | 不依赖原图的 JS/Python 重放和预算检查 |

本轮不会把人工开发的拟合器记为系统自主 L2 RSI，也不会用模拟 LLM 回应冒充真实调用。若没有已配置模型凭证，界面保留真实不可用状态；画质交付仍通过实际参数优化与计算完成。

## 5. 模块与数据接口

新增 Python `fitting/quality12.py` 与 `scripts/fit_quality12.py`，复用已有稀疏矩阵和原生解析梯度基础。CLI 接收参考路径、固定预算、输出路径，可在本机对用户自己的观察重新运行。

资产封装 `crf.quality_asset.v1`：`gaussian` 内含已有 `crf.gaussian_asset.v0.8` 数值约定，外层保留来源、参考摘要、求解配置、质量契约摘要及拟合历史。旧资产解析器与 URL 不变。

工程封装 `crf.quality_project.v1`：资产、视口、图像参数及来源声明。默认 identity 状态对应冻结验收；编辑后界面明确标记历史指标不代表当前输出。工程保存与重新导入必须保留所有计算所需参数。

新增 `web/crf-quality12.js` 为浏览器与 Node 共用纯函数内核；`web/quality-worker12.js` 在 Worker 运行，不取原图，不静默降采样。内核遍历各高斯的有限支持域，避免每像素扫描所有核；默认 Float64 累计，保留确定顺序。输出最多 4M 像素、200M 支持域访问，超限给出明确错误。取消或新请求不能让过期结果覆盖新画面。

视口 `roi=[x0,y0,x1,y1]` 表示源图归一化连续边界。输出第 `(i,j)` 像素在 `u=x0*W+(i+0.5)*(x1-x0)*W/outW`、`v=y0*H+(j+0.5)*(y1-y0)*H/outH` 处重新求值；2×输出不是将已有 RGB 图片插值。重新采样不会凭空恢复相机原图中未保留的内容。

新增质量工作台 `/quality12.html`，链接到原 `/studio11.html`。默认显示计算结果，按需打开单独参考对照；提供原生/2×计算、固定 ROI、图像参数、声明代码、工程 JSON 导入导出、PNG 输出。曝光和色彩操作是显式图像变换，不称为物理重光照。

## 6. 资源与兼容

保持原 17 个入口及全部旧公共资源逐字节相同。构建总量仍遵守 250 MiB；不通过删除历史资产或放宽上限腾空间。新增参数采用公开的无损传输压缩，若需改进历史资源打包，必须重新逐 URL 检查返回原字节，并保留旧归档恢复检查。

## 7. 验证与交付规则

1. 从序列化最终资产计算 Python 原生 PNG，按固定契约评价全图及三个 ROI。
2. 独立 JS 在没有参考图输入的情况下重算 PNG，与 Python RGB8 最大通道差 ≤1；报告精确相同像素比例。
3. 检查原图/结果并排和三个 ROI，不用缩略图掩盖细节问题。
4. 实际浏览器执行加载、编辑、2×函数重算、恢复、保存、导入及 PNG 导出；下载文件须独立读回并重放比较。
5. 验证核心旧测试和原资源字节、构建体积、未配置凭证边界。新增测试覆盖真正的坐标、预算、编辑、取消与文件重放风险。
6. 交付说明优先给图片、真实参考误差和实用入口，再给性能及工程测试。不存在的 GPU、真实 agent 生成或视频动力学不得写成已完成。

若本轮候选未过硬门槛，继续改进表示与优化；不降低门槛，也不以测试数量取代画质。完整 CRF 1.1 的形式证明、真实程序 RSI 和通用创作闭环仍保持各自真实状态。
